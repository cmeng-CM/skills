# 与现有 skill 的衔接

本 skill 只做**计划 → 执行 → 验证**。上游的需求澄清、下游的收尾写回各有专门的 skill，这里只定义交接点。

**所有衔接都是条件调用**：先探测目标 skill 是否存在，不存在就走降级路径，绝不让流程卡住。

## 探测方式

skill 装在两处，任一命中即可调用：

```
~/.claude/skills/<name>/SKILL.md     # Claude Code
~/.agents/skills/<name>/SKILL.md     # 跨工具标准路径：ZCode / Codex / pi 都读这里
```

（项目内也可能有 `.agents/skills/` 或 `.zcode/skills/` 的本地副本，一并看一眼。）

探测就是看 `SKILL.md` 在不在。探测不到就**不要**提这个 skill，直接走降级——避免让用户去找一个不存在的 skill。

---

## 不在衔接范围内：收尾写回

**本 skill 不收尾写回，也不判断该不该写回。**

工作流跑到"验证通过 + 报完账本"就结束。要不要把产出写回别处——更新项目契约、写入长期记忆、把知识归位、生成周报——是**用户的判断**，不是工作流的判断。所以：

- **不探测**任何写回类 skill 是否存在
- **不代判**该不该写回、写回什么
- **不代办**、也不建议"要不要我帮你写回"

用户明确要求写回时，那是用户发出的一个新指令，按该 skill 自己的协议执行即可——与本工作流无关。

**本 skill 绝不写**：长期记忆、项目契约、知识目录、周报。收尾只产生两样东西——账本里的记录，和给用户的报告。

## 上游一：delve（需求澄清）

**触发时机**：P 轮开头，判定需求是否够清楚的时候。

**判据**——出现以下任一情况就该调用：

- 同一句话能合理理解成两种不同的东西
- 目标里出现无法定量的形容词（"优化一下"、"更流畅"、"好用一点"）
- 用户没说的关键决策会影响计划结构（技术栈、范围边界、兼容性要求）
- 计划里有决策项写不出来（说明需求本身没定）

**调用方式**：把歧义点交给 `delve`，由它一次问一个决策问题。

**降级路径**（delve 不在）：自己一次问一个问题，把答案写进计划的决策表。**不要**为了显得高效而一次列五个问题，也不要在需求有歧义时硬出计划——那正是"计划会乱"的源头。

**不触发**：需求清楚、方案明确时直接进 P 轮。别为了走流程而走流程。

## 上游：拿项目约定与验证命令（不依赖外部 skill）

**触发时机**：P 轮开头——需要知道项目的验证命令与必须遵守的约定。

**做法**：直接读项目根的 `AGENTS.md` / `CLAUDE.md` / `README.md`。这三样能给出：

1. 项目用的是什么测试/构建命令（V 轮的验证命令来源）
2. 项目有哪些必须遵守的约定（会进计划的全局约束）

**读不到时**：直接问用户"这个项目的验证命令是什么"，答案写进 plan.md 的验证命令块。一次问清，之后每次验证都用它。

**注意**：验证命令拿不到时，**不要**自己猜一个（比如默认写 `npm test`）。宁可标 `未声明`，V 轮走人工确认。

## session-handoff（换人/换 agent 接手）

**触发时机**：工作流**未完成**但需要中断时——上下文将满、要换工具、要换人接手。

**先说清楚**：**账本已经能做恢复**。同一会话或新会话里说"继续"，读 `.workflow/<slug>/ledger.md` 就能接上。所以**跨会话续做不需要 handoff**。

handoff 真正必要的场景：

- 要**换一个 agent 或换一个人**接手，对方需要完整的"为什么这么做"而不只是进度
- 需要把决策链的理由（而不只是结论）传递出去
- 要暂停很久，届时可能已经忘了上下文

**调用方式**：按 `session-handoff` 的 CREATE 协议生成交接文档，在文档里指明工作流目录与当前任务。

**降级路径**（handoff 不在）：在收尾报告里直接给出 resume 指令——`读 .workflow/<slug>/ledger.md 和 plan.md，从 <任务> 继续`。

## 明确不衔接的

| skill | 为什么不接 |
|---|---|
| `project-learning` | 它解决的是"理解一个陌生项目"，不是"完成一个任务"。在做任务的过程中插入学习流程会让执行轮变重，且两者的产物（认知地图 vs 计划账本）没有交集 |
| `memory-write` / `memory-compile` / `memory-project-context` | 它们是写回长期记忆的通道；收尾写回本身就不在本 skill 范围内（见上文），本 skill 也不直接调用它们 |
| `meeting-summary` / `md-to-docx` / `svg-to-editable-pptx` | 工具型 skill，与任务工作流无结构关系。任务需要时把它们当作普通工具使用即可 |

## 一个实际的坑

skill 装在两个目录：`~/.claude/skills`（Claude Code）与 `~/.agents/skills`（ZCode / Codex / pi）。出现"明明装了却调不到"时，先确认它在**当前客户端**读的那个目录里——只装在一起不会被另一处看到。

调用前统一按上面的探测方式检查，不要假设装在同一个地方。
