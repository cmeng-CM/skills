# ZCode 项目记忆迁移

ZCode 把每个"工作区"（会话启动目录）的项目记忆存在 `~/.zcode/cli/memories/projects/<slug>-<hash16>/memory/`，记忆键由目录的绝对路径派生——目录改个名或换个入口路径，键就变，记忆看着就"丢了"。本 skill 负责四件事：**看懂键怎么算**、**盘点键对应哪个目录**、**把记忆从一个键迁到另一个键（含合并）**、**多入口共库（软链）**。

**守卫：**
- **只动记忆库。** 只操作 `~/.zcode/cli/memories/` 下的文件与软链；不碰项目目录、不碰 agent-memory（Obsidian Vault `60-Agent-Memory`，那套有自己的 memory-write / memory-compile）。用户要"改某条记忆的内容"——那是主记忆协议的事，不是本 skill 的活。
- **先校验，后删源。** 迁移 = 复制 → 逐文件 diff 校验 → 才删源；校验不过立即回滚目标侧本次复制，源保持原样。
- **键必须哈希核对，不许猜。** slug 前缀会撞车（两个项目的 `80-code/` 目录分别生成 `80-code-<不同 hash>`），判断归属一律用脚本对候选路径重算 sha256 验证，不许凭目录名或前缀下结论。
- **没说动就只看。** "查一下记忆在哪"是只读盘点；只有用户明确说"移动/迁移/合并/共用"才写。

**反模式（明确不要做的事）：**
- 不要手工拼 `<slug>-<hash>` 猜键——hash 不可逆，必须对候选路径逐个重算验证
- 不要 `mv` 整个目录了事——合并场景要先逐文件比内容、并 `MEMORY.md` 索引，避免覆盖目标已有记忆
- 不要把"改名后记忆不见了"当成丢数据——文件都还在旧键下，迁移即可
- 不要在旧键留一份"备份副本"——两处各长各的，很快分叉（要两处都能用就走变体 A 软链）
- 不要改记忆文件的内容——迁移只搬文件（唯一例外：`MEMORY.md` 索引行合并）

## Working Protocol

### Step 0 概念：记忆键怎么算（与 ZCode 运行时实现一致，已实测验证）

```
slug   = basename(resolve(工作区路径)) 小写化 → 非 [a-z0-9._-] 字符替换为 "-"
         → 去首尾 "-" → 截前 48 字符（为空则 "project"）
hash16 = sha256(resolve(工作区路径)) 的前 16 位十六进制（Windows 上路径先小写）
记忆目录 = ~/.zcode/cli/memories/projects/<slug>-<hash16>/memory/
```

本机实测样例（可作回归样例）：

| 工作区路径 | 记忆键 |
|---|---|
| `/Users/cm/workspace/10-物料主数据` | `10-2ca07203186bab20` |
| `/Users/cm/workspace/10-物料主数据/80-code/ai-mdm` | `ai-mdm-2aee8b89077b570b` |
| `/Users/cm/workspace/11-中化高纤/80-code` | `80-code-89e12ba02dc18768` |
| `/Users/cm/workspace/10-物料主数据/10-POC/材料主数据编码审核智能体` | `project-5228975f42abfb4c`（纯中文目录名 → slug 回退 `project`） |
| `/Users/cm/workspace/obsidian/obsidian-repository/20-Projects/10-物料主数据`（经软链） | `10-ef1219755fb43707`（≠ 真实路径的键） |

两个坑，必须记住：

1. **软链不解析**：`resolve()` 只做绝对化和规范化，不解析符号链接。同一物理目录经不同路径（真实路径 vs Vault 软链）打开会生成**两个键、两份记忆**。
2. **`project-<hash>` 键有两个来源**：① 工作区设置了 workspaceIdentity 时，slug 固定为字面量 `project`、hash 取 identity 字符串的 sha256（无法按路径反推，只能读内容判断）；② 目录名不含任何 ASCII 字符（如纯中文目录「材料主数据编码审核智能体」）时，slug 清洗为空、回退为 `project`——这种情况 hash 仍按路径算，`find`/`inventory` 可以正常匹配。

每个键的目录结构：`MEMORY.md`（索引，每行 `- [标题](文件.md) — 钩子`）+ 若干记忆文件（frontmatter + 正文）。记忆在**会话启动时**加载——迁移完成后，需新开会话才会按新键加载。

### Step 1 定位 / 盘点（只读）

```bash
python3 scripts/zcode_memory.py inventory                  # 盘点：全部键 → 归属目录 + 文件数
python3 scripts/zcode_memory.py key <目录路径>              # 正向：某目录 → 它的记忆键
python3 scripts/zcode_memory.py find <键 或 目录路径>       # 反查：这个键是谁的
```

- `find` 对键的处理是"扫候选根目录、对每个路径重算 sha256 匹配"；扫不到时说明可能是 workspaceIdentity 键、目录已改名/删除、或曾经经软链路径打开——用 `--roots` 追加扫描根。
- 哈希之外交叉核对内容：读该键的 `MEMORY.md` 索引行，通常一眼能看出属于哪个项目。

### Step 2 预检：迁移 vs 合并

对源、目标各跑一次 `key`/`find`，确认三件事：

1. 源目录存在且非空（空 = 无事可做）。
2. 目标确实是用户期望的项目根目录。🔴 **CHECKPOINT：把"源路径→键、目标路径→键"的对应关系展示给用户并确认目标路径**——多入口项目里目标选错会制造第三份记忆。
3. 目标是否已有记忆：空 → 直接迁移；非空 → **合并**：
   - 逐文件比内容：一致 → 跳过；不一致 → 冲突。🔴 **CHECKPOINT：逐文件列出差异，等用户裁决保留哪份/改名并存/跳过；裁决前不覆盖、不删源。**
   - 索引合并：源 `MEMORY.md` 的行并入目标，重复行去重。

### Step 3 执行迁移

```bash
python3 scripts/zcode_memory.py move <源：键或目录> <目标：目录路径>   # 复制→校验→删源→并索引
python3 scripts/zcode_memory.py move <源> <目标> --keep-source        # 只复制不删（用户要"拷一份"）
python3 scripts/zcode_memory.py move <源> <目标> --dry-run            # 只出计划，不写文件
```

脚本不可用时的手工等价步骤：

1. `cp` 源目录下除 `MEMORY.md` 外的文件到目标目录（目标不存在先建）；
2. 逐文件校验（`diff -r`）必须完全一致；
3. 合并两份 `MEMORY.md`（重复索引行去重；目标没有则直接采用源的）；
4. 确认校验通过后，`rm` 源目录里的文件（空目录留着，ZCode 自会管理）。

### Step 4 收尾

- 报告按 Exit Protocol。
- 明确提醒行为变化：**旧目录开会话将看到空记忆**（键还在，文件搬走了）。
- 若用户还会从旧入口开工 → 给共库方案（变体 A），不擅自建软链。

### 变体 A：多入口共库（软链）

让两个入口（如项目根 + 代码子目录）共享同一份记忆：

```bash
ls -la <次入口记忆目录>              # 先确认它是空目录或已完成迁移
rm -rf <次入口记忆目录>
ln -s <主记忆目录的绝对路径> <次入口记忆目录>
```

已知局限：ZCode 升级或存储重建时可能把软链替换回真实目录（共库随即断开）——迁移/共库后提醒用户，隔段时间用 `ls -la` 复核一次。

### 失败分支

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| `find` 扫不到键的归属目录 | `--roots` 追加扫描根（含软链路径所在根） | 读记忆内容人工判断归属，报告中注明"未能哈希确认"，不写任何文件 |
| 目标已有同名记忆且内容不同 | 停下，逐文件展示两版差异 | 用户裁决：保留目标 / 用源覆盖 / 改名 `-v2` 并存 / 跳过该文件 |
| diff 校验失败 | 删除目标侧本次复制的文件（仅本次），源不动 | 报告并终止，建议检查权限与磁盘状态 |
| 迁移后旧键又出现新文件 | 说明：该入口又开过会话，写入按旧键落盘 | 建议改从目标入口开工，或再次迁移/共库 |

## Exit Criteria

- [ ] 源、目标两个键均已哈希核对（报告里给出 `路径 → 键` 对照）
- [ ] 复制完成后逐文件校验一致（报告里给出校验结论）
- [ ] 合并场景：同名冲突已停下并由用户裁决，未覆盖任何文件（未裁决则中止且源完好）
- [ ] `MEMORY.md` 索引已并入目标、无重复行
- [ ] 删源发生在校验通过之后；`--keep-source` 时未删源
- [ ] 除 `MEMORY.md` 索引合并外，未改动任何记忆文件的内容

## Exit Protocol

1. 报告：迁移了哪些文件（数量 + 源键 → 目标键）、校验结论、源现状、目标现状。
2. 明确说明行为变化："从现在起，在 `<源目录>` 开会话看到的是空记忆；记忆只随 `<目标目录>` 加载。"
3. 若检测到用户仍会使用旧入口，附上共库方案的一行命令（变体 A）；不擅自建立软链。
