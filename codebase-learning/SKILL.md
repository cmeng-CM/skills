# 源码学习导航

帮助用户建立能够解释、推演和评价项目的心智模型。AI 负责研究、组织与解释，用户选择学习方向、阅读实际源码并共同讨论；学习目标覆盖架构与关键机制。

## Working Protocol

### 1. 确定项目与当前学习位置

- 承接用户已给出的项目、版本、目标、背景和学习记录，不重复访谈。项目对象不明确、路径包含多个独立项目或版本选择会改变解释时，只询问当前必要的信息。
- 支持本地源码与可访问的远程仓库。使用环境已有的搜索、读取与代码导航能力；遵循目标仓库约定，存在可用索引时按其规则复用，不要求预先安装特定图谱、服务或其他 skill。
- 记录实际分析的分支、提交或标签，以及会影响结论的工作区修改。没有 Git 信息时记录可识别的源码来源与分析日期；远程资料不能与本地不同版本的实现混用。
- 先检查已有学习材料。默认按“阶段一项目地图 → 阶段二模块建议 → 等待用户选择 → 阶段三深度指导”推进；用户只要某阶段时按该范围交付。已选定模块或跨模块问题时直接进入阶段三，补足必要的整体背景，不强制重做完整总览。

### 2. 组织和保存材料

默认使用“对话摘要＋Markdown 学习材料”。用户指定输出位置时优先采用；否则保存在目标项目根目录的 `.codebase-learning/`：

```text
.codebase-learning/
├── overview.md                 项目地图＋模块学习建议，作为统一入口
├── modules/
│   ├── <topic>.md              用户选定模块或跨模块主题的深度指南
│   └── <topic>-skeleton.md     复杂主题的一页骨架，可省略
├── assets/<topic>/             指南中渲染后的图，按 NN-名称.png 命名
└── validation-<topic>.md       阶段三的实际检查与未覆盖项
```

- `<topic>` 采用简短稳定的主题名，同一主题继续更新原文。总览链接到已生成指南，指南链接回总览；沿用已存在且由用户认可的材料目录，不另建副本。
- 在写对应阶段前，读取 [学习材料规范](references/learning-standard.md) 的通用规则和当前阶段要求；按需使用 [总览模板](assets/overview-template.md) 或 [深度指南模板](assets/module-guide-template.md)。规范是内容要求的真源，模板提供编排骨架，合并章节不能丢失必需信息。
- 用户明确只讨论或不写文件时，在对话中呈现相同的内容与图表。保存受阻时如实说明已完成内容和未保存范围，保留可交付正文，不声称已落盘。
- 研究默认读取源码、测试、配置和文档，写入限定为学习材料。需要运行项目或实验时，说明验证目的、环境要求及可能写入，按已有授权执行；不自动修改业务源码、安装依赖或提交变更。

### 3. 建立项目地图与模块建议

从项目目的和约束出发，检查入口、配置、核心概念、模块边界、代表性调用路径、外部交互与相关测试，形成整体认识。目录结构和导入关系是定位线索，不能单独证明职责划分或真实运行行为。

按职责划分模块并映射到源码，追踪横跨模块的关键机制。默认完成阶段一、二，写入同一份 `overview.md`：

- 阶段一包含系统结构图、典型运行流程图和模块／源码导航；让用户能够解释整体如何工作并找到阅读入口。
- 阶段二覆盖已识别的主要模块，给出具体学习问题、价值、前置知识和顺序理由。必要前置、建议顺序与可独立学习分别表达，不把调用关系直接当作学习依赖。
- 交付后概括推荐起点，等待用户选择模块、机制或跨模块问题。用户尚未选择时，不自动生成所有模块的深度指南。

### 4. 围绕选定主题生成深度指导

读取实际实现及相关测试，检查上下游路径，按规范组织导读、模块全貌、逐项机制解析、贯通场景与源码路线、理解收束。所选范围内影响行为、能力边界与关键取舍的机制都应进入清单；尚未核实的机制保留为具体缺口。

- 每个关键机制覆盖：问题与必要性、基本原理、实际运行方式、关键约束与边界、设计取舍、源码观察点。按机制组织主体，复杂主题按依赖分节，简单内容可自然合并。
- 逐项机制解析必须在机制附近附源码摘录：文件、符号、起始行，单段约 10~30 行，保留支撑结论的类型、分支和状态写入，省略处标注。只给代码位置不算完成；确实无可摘录实现时说明原因。
- 指南必须有解释机制的图、源码主链与跳查路线、设计取舍表。能渲染时把图渲染为图片嵌入正文，并用可折叠块保留 Mermaid 图源；不能渲染时说明限制。用代表性场景串联机制；存在影响结果的异常、并发、取消、恢复或生命周期行为时，纳入解释。
- 源码路线分两层。主链串读先由机制清单推导一条贯穿命题，按真实调用顺序分站，每站交代从上一站哪个调用或事件进入、本次要回答什么、得到什么才进入下一站，并配调用链图；关键站点直接附源码摘录，让读者在主链上完成第一次核对。读完全线应能复述整章如何运转。按目的跳查表负责定位，不替代主链。主链形式由主题决定；确实没有过程主线的主题须说明理由。
- 机制较多或主链较长的复杂主题，补一份一页骨架，把整体位置、转折点和检查题钉住；骨架不引入新机制，也不作为阅读门槛。
- 关键解释附近提供可核验入口，避免只在文末堆文件清单。有相关测试时指出测试文件与用例名，并注明是否执行。
- 阶段三结束后写验证记录：材料检查、关键判断的证据、未覆盖项和修改范围；只写实际执行过的检查。
- 依约束分析收益、代价、替代方案与适用条件；实现可能体现设计选择、兼容妥协、历史遗留或缺陷。证据不足时保留判断，不替作者编造理由，不凭结构断言性能或正确性。
- 区分作者明确说明、实现可确认的事实和分析推断。没有运行的测试只代表可阅读的预期；静态推演、实际观察和实验结果分别表述。

### 5. 继续讨论与维护

- 依据用户读源码时的疑问补查、解释并更新对应章节；形成新结论后同步相关图表、路线和总览链接，避免把有效内容分散成连续追加的聊天摘录。
- 补充必要背景或源码细节，以能够推演机制为深度标准。理解检验、运行实验、代码练习和复习安排按用户需要提供，不设置强制答题门槛。
- 继续旧材料前核对当前主题的源码变化；有影响时更新或标明过期内容，解释依据不同版本时注明差异。无关变更不要求重建全部材料。
- 仅记录已分析、已生成、待核实等材料状态。指南生成、用户读过和用户掌握分别看待，不根据“可以”或文件生成自动宣布掌握全部机制。

## Exit Criteria

- [ ] 当前阶段符合实际请求；范围、源码基线与重要未核实项可识别。
- [ ] 总览、建议、指南中的模块和概念一致；运行关系、学习依赖和源码位置能够对应。
- [ ] 当前阶段必需信息与图表已覆盖，图能解释问题，表能支持导航或比较，正文有连贯讲解；图有可读呈现（渲染图片，或明确说明渲染限制）。
- [ ] 阶段三的主链关键站点附有源码摘录，而不是只在机制章节给代码。
- [ ] 关键判断有已检查的证据；收益、代价与条件具体，推断和未实测结论没有冒充事实。
- [ ] 已保存材料与实际链接可访问；阶段三验证记录与总览互链，且只写实际执行过的检查；未保存或未完成的部分如实说明，没有遗留模板占位内容。
- [ ] 停在本次范围内，等待选择或继续讨论，没有自动扩展到全部深挖、业务修改或学习验收。

## Exit Protocol

先给本阶段最重要的认识和材料链接，再说明影响理解的缺口。完成阶段二后给出推荐起点及理由，邀请用户选择；阶段三结束时指出源码阅读起点和可继续讨论的问题。只请求阶段一时按该范围交付。对话摘要不重复整份材料，也不代替保存正文。

维护本 skill 时使用 [行为案例](tests/behavior-cases.json) 检查触发、阶段衔接、图文输出与证据边界。案例定义、作者自检、实际模型执行和独立评测分别记录，不能相互替代。
