## 3. 实现质量与测试意义

新增测试使用真实临时文件、账本和独立 Python CLI 子进程，不是仅搜索文案：

1. **隐藏目录中两任务接续**：T1 已接纳而 T2 未接纳，新进程 status/next 能区分状态并只将 T2 作为未完成实施候选；完成覆盖两任务的审查和真实命令后，新进程看到运行已完成但验收仍 pending，再显式 record/close。证明状态从持久数据恢复，不依赖原 Engine 对象内存。
2. **中断留下未记录改动**：已记录实施后改产品，再建 Engine，原记录变 stale，审查/验收不能自动通过，close 被拒绝。证明不能凭旧状态认可新部分改动。
3. **旧路径兼容**：在 `docs/delivery/` 建立目标，新 Engine 读取既有结果并正常关闭，无迁移路径或重写历史。
4. **init 后未 configure**：独立 CLI 返回 `configure required`，正常接纳配置后可继续实施，初始 init 事件保留。证明这一中间状态是可继续的配置缺口，而非要求删除 runtime。

这些用例模拟在明确边界停止并用新对象/新CLI接续；没有执行任意时刻杀死协调进程、自动恢复未保存上下文或跨模型自主接续。因此测试结论应表述为“本地持久状态、跨进程读取与门禁恢复路径已验证”，不能扩大为所有中断情形或完整agent编排都已实测。
