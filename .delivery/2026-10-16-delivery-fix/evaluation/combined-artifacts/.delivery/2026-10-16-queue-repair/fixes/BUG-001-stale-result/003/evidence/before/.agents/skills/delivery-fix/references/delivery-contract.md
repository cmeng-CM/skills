# Delivery Fix 交付约定

本文件定义 `delivery-fix` 的输入输出语义契约，当前版本为 **1**。完整专业内容见[修复报告规范](fix-standard.md)。契约是人和模型可读的 Markdown；独立使用不要求运行引擎、其他 skill、Git 或机器接纳格式。

## 输入、权限与输出

输入至少包括可定位的故障现象、项目或实际对象、期望行为的依据、诊断或修复授权及已知限制。已有日志、复现方法、方案、计划和历史报告按实际提供，不为使用 skill 补造前置文件。关键输入不足时先完成授权内的调查，不能假定用户预期、伪造复现或越权修复。

输出包括诊断依据、实际修改、实验处置、针对性自检、未决项和可恢复交接。只完成诊断也是可保存的成果，但不等于修复完成；缓解有效不等于根因解决；作者自检不授予独立审查或交付验证通过。

独立使用默认不提交。编排可依据明确任务安排本地提交、不 push；用户或项目明确规则优先。skill 不主动组织跨能力流程、不读写编排账本或改写他人结论。

## 目录与轮次

- 新目标默认在项目 `.delivery/YYYY-MM-DD-主题/`，日期取创建日，同目标跨日续用。已有明确目标目录或用户指定位置优先，不移动历史目录。
- 同一 bug 使用稳定目录 `fixes/BUG-001-问题简述/`，内含 `index.md` 和编号轮次目录 `001/`、`002/`；每轮报告为 `fix.md`，该轮证据置于其 `evidence/`。
- bug 标识与目录归属先查现存记录。多个候选无法确定时提出具体冲突，不覆盖、擅自合并或重复建同一问题。已有正式问题 ID 可直接沿用，不要求转换为 `BUG-001`。
- 新任务再次处理同一 bug，引用既有 bug 目录并在其中新建轮次，写明新任务归属与授权。旧任务关闭事实保持不变；引擎需要新的复发问题 ID 时保存关联，不能用复发覆盖旧关闭结果。目录不可访问或项目权限不允许写入时交由调用方决定，不能悄悄改归属。
- 每轮可包含多次调查、实验和会话。正式交接、提交审查或被接纳前持续维护；任一上述动作发生后保留该轮内容，后续新建轮次并说明承接和修正范围。
- 创建前检查编号；并行执行者由调用方分配唯一写入范围与索引维护者，不共同写同一轮报告或共享证据文件。
- `index.md` 只保存稳定问题身份、归属、关联任务、轮次入口与最新记录链接，不维护第二份实时状态。接纳与证据绑定具体轮次，不能绑定会变化的“最新”指针代替事实版本。
- 证据按实际需要保存，不预建空文件。正式活动默认留存，包括失败和阻塞；用户明确仅对话时遵从，保存受阻时准确说明。

## 报告身份与可恢复性

| 信息 | 要求 |
| --- | --- |
| 问题和范围 | bug 标识、现象、目标/任务/原问题关联、当轮实际范围；无正式任务 ID 时用明确文字定位 |
| 报告身份 | 轮次、报告版本、作者、时间、文件位置、前次记录及承接/修正范围 |
| 实施作者 | 当前实际修复者、前序及共同修改者，列出各自涉及的实际成果；报告编写者与实施者分别说明 |
| 生成规则 | `delivery-fix`、契约版本 `1`、实际 skill 修订及可恢复来源 |
| 输入与授权 | 相关需求/设计/计划及版本、真实授权入口、允许动作、验收要求 |
| 产品身份 | 实际调查和修复前后对象，相关未提交/未跟踪内容、必要快照或差异 |
| 结论与限制 | 诊断确定程度、修复或缓解成果、自检范围、未决及后续责任 |

skill 修订、专业契约版本、报告版本和产品版本分别记录。有未提交改动时不能仅用 HEAD 代表实际内容；无 Git 时用内容指纹和可恢复快照或等效来源。未知身份或不可恢复部分如实说明，不编造哈希或已确认事实。

作者链按实际成果继承；移交或换 skill 不删除前人参与。调用方据此核查独立性，不能只排除最后写报告的人。尚未核实的作者明确标记缺口，不能当作空集合通过。

## 组合接纳与历史

调用方核对契约兼容、实际来源、目标范围、授权、产品版本、完整作者和未决项后，可直接引用本轮报告作为实施类产物；不要求复制同内容的实施文档。若编排尚未支持此能力，明确未接入，不能冒用其他 skill 的名称或来源。

已有独立报告接入时检查有效性，不补造历史授权、假装重新执行或为了格式无意义重做。诊断进度由报告表达，运行准入、正式任务状态、独立审查、验收与收尾仍由调用方负责。

已固定报告发生纠错时建立关联补充记录；历史失败、证据和当时判断不删除。发现证据或产品变化，指出可能受影响的旧结论并通知调用方，不能自行删除整个目标的有效结果。风险接受事实单列，不回写为技术符合。

维护时区分内部方法改进、兼容扩展与破坏性契约变化。改变必要输入、必需输出或结论含义须评估影响，破坏性变化升级契约并同步调用方。版本相同不自动证明质量不下降；进行中活动不静默切换规则，历史记录不批量重写。
