# 评测协议：修改前冻结

版本 1；2026-10-16。依据已确认计划第 5 章。该文件定义方法，不记录通过事实。

## 比较对象

- legacy：`evidence/baseline/sources/task-workflow/`，原稳定格式；试验格式单列。
- baseline：`evidence/baseline/sources/delivery-*`，含本轮开始前的未提交修订。
- candidate：`delivery/delivery-*`，执行前保存精确来源和文件摘要。

三个候选对共同适用的同一实现需求使用相同模型、配置、输入数据、工具权限和执行预算。独立调用是 delivery 的独有能力，不给旧 workflow 编造不适用成绩。来源冻结后，不让运行读取更新中的安装副本。

## 输入与判据隔离

公开输入包含完整用户需求、验收标准、正常项目代码/测试及对应 skill；评审私有材料包含隐藏缺陷位置、注入说明、参考答案和评分细则。私有材料不进入被测工程、提示词、检索上下文和工具输入目录。评审者在执行后查看真实产物和私有判据。

运行器保存完整输入、事件、实际产物、命令结果、执行版本和环境，并检查私有材料泄露。不能提供所需访问隔离时须明确限制；发生泄露的运行不计作自主发现能力的质量证据。

## 硬性条件

1. 实际行为满足公开需求；遗漏消费者接入、数据规则或失败行为则失败。
2. 五项独立能力分别在无其他 delivery 包、无编排器、无 `.workflow` 的无 Git fixture 运行；不得自动串联或提交。
3. 完整组合必须实际生成设计、计划、实现、独立实现审查、验收和收尾；任务包含共享契约、两个功能分支、消费者接线及联合验证。
4. 缺必需审阅、同作者审查、映射缺项、未授权降低验收、过期依据、未知运行不得被收尾为全部通过。
5. 范围外变化、skill 更新和中途中断应保留真实历史，按影响复核；未知副作用不得盲重跑。
6. 假绿测试、全部跳过、mock 绕过集成、错误交付对象不得证明验收通过；oracle 自身有效与 agent 能自行发现分别证明。
7. 合法等价修复应被接受，已授权局部实现不得反复请求批准，联合验证不得自锁。
8. 无可用真实模型接口须 not-run；fake 适配仅验证 harness，不计作真实模型运行。

## 初始执行安排

五项独立调用各执行正常场景，并覆盖其适用反例。代表性的完整组合与中断恢复对三个候选各初始重复两次；出现差异保留全部结果并诊断。行为门禁负例在 candidate 上实际执行，确定性运行时负例另做单元/CLI 验证，不混算为模型能力。

语义评审由非实现者根据真实产物逐项判断：需求覆盖、实际功能、审阅独立性、证据有效性、恢复、可读性。评审隐藏候选标识时记录盲评范围；原始轨迹可追溯但不让被测者访问评分答案。任何可复现的质量退化阻塞交付，不用平均分或最好一次覆盖失败。

质量达标后才比较时间、token、重复操作和人工介入。小样本只证明已执行案例，不外推所有大任务。评测运行记录归 `evidence/behavior/`，逐案例列明已执行、失败、未执行与限制。
