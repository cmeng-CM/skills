## 1. 专业计划结论

已从用户目标、B1—B11、设计 v1.1 反查 T-05—T-08 的增量。设计 2—3 章的显式 v2 入口、configure 待准入、专业/映射身份排除、来源绑定由 T-05 承接；4 章监测与影响由 T-06 承接；5 章实际加载来源和 source-update/transition 由 T-07 承接；6—7 章简报、资源、尝试诊断和未知运行解除由 T-08 承接。未知运行仅解除不能收尾、需新 run/verdict 替代链的限制没有漏掉。

任务、验收和验证组 ID 保持；原全局覆盖没有因细化删项。设计检查只依赖 T-02，未反向依赖 T-05；T-06/T-07/T-08 的产物可接入与共享文件交接分开；V-03/V-04 完成后才启动正式 V-06，没有要求它们先于形成自身所需代码。整体审查等产物形成后执行，不形成实现自锁。专业卡在本次范围内足以开始对应实现，实际门禁是否执行仍需独立检查真实活动。

非阻断的记录清理：计划 6.1 仍写 runtime “本轮尚未建立”，7.1 仍混用初版 7 张卡的机械结果描述与已细化全部卡的新限制。历史结果可以保留，但应明确时点，避免恢复时误读成当前不存在 runtime 或当前机械检查只有 7 张卡。这些不改变任务定义或授权，不作为本次主要阻断。

## 2. 映射结论与问题

控制配置保留 11 个任务、整体 R-all 与全部 7 个必需 V 组，授权摘录真实，未删去整体验收或将硬约束设为可豁免。旧 v1 不自动具有 v2 的 mapping/design/plan/change gates，这一点已在 mapping_reason 中如实说明，应保留人工判断证据。

### PR-003：全部 depends 为空，遗漏稳定 v1 可以表达的实施依赖

- **触发：** 使用控制配置 002 从任务状态恢复或接纳 T-05/T-06/T-08 等结果。
- **预期：** 正文已有依赖在机器可表达时进入同一接纳图；无法表达的可接入细节、专业身份和新门禁由明确人工核对补足，不能把可以表达的部分一并丢掉。
- **实际与证据：** 11 个 task 的 depends 全为 `[]`。但计划 3.2 与任务卡明确 T-05 依赖 T-02/T-03，T-06 依赖 T-05，T-08 依赖 T-06/T-07。冻结 v1 API 第 2 章和 delivery.py 已支持 `{"kind":"implementation","id":"T-05"}` 等图依赖及联合循环检查。
- **影响/阻断：** 稳定控制器可以把关键前置未形成的结果视为可接纳；新会话的机器 next 不反映正文次序。当前 mapping_reason 只对“v1 不能表达的新门禁”给人工说明，不能覆盖本遗漏。阻断当前映射通过，不表示已有作者实际越过了门禁。
- **关闭条件：** 对正文逐条核查，映射 v1 可表达的实施/验收依赖，保留精确产物可接入与独立专业门禁的人工边界；如刻意只用保守最终汇总控制，则需明确列出所有不编码的条件及逐次人工准入核查记录，证明不会被机器 next/record 当成可无条件推进。新配置与正文联合推演不能引入循环，旧事件不改写。

### PR-004：根导航产品没有纳入版本绑定

- **触发：** T-11 修改 README.md/CLAUDE.md 后完成 R-all/V-07，再次误改根导航或调用入口。
- **预期：** 本目标实际交付的导航与安装指引属于对应产品或审查/验收上下文，影响判断的变化使结论过期。
- **实际与证据：** T-01 scope 只有 install-skill.sh；T-02—T-11 均只有 delivery。R-all/V-07 没有补 context_scope。正文 T-11 明确包含根 README 导航，实际 root 已写 README/CLAUDE 增量；它们都不在控制绑定范围。旧 v1 API 第 1 章已支持产品 scope 和 context_scope，无须新字段。
- **影响/阻断：** 最终导航损坏或被替换后，原整体审查/验收仍可能 current，不能证明最终交付版本有效。阻断当前映射通过；不要求把原三个受保护 skill 纳入本轮可修改产品。
- **关闭条件：** 将实际受改动/依赖的根导航、说明或必要上下文纳入相应范围，审查最终版本并绑定。路径存在及范围覆盖应直接检查；不能只在报告里写“全部已覆盖”。

## 3. 保守映射限制与后续

七个 V 全覆盖 11 个 task，比正文各组更宽；这样不会漏掉最终验证，但会扩大失效并让早期验证在账本中等待无关任务。可以为一次性的稳定控制选择保守汇总，前提是明确说明它与正文实际阶段门禁不同，V-01 的命令回执不能单独证明 12 个链接/历史保护，也不能代替正文指定的独立检查。不要把保守控制账本用于证明候选 v2 已实现定向失效/高粒度复用。

当前没有修改正文或配置。主协调修订后应保存新的配置版本及重接纳依据，并按 PR-003/PR-004 定向复核。专业计划“可交接”不等于控制映射通过，更不等于未来实现或真实行为已验收。
