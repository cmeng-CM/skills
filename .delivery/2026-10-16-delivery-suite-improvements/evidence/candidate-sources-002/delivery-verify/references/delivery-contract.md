# Delivery Verify 交付约定

本文件定义 `delivery-verify` 的输入输出语义契约，当前版本为 **1**。完整专业内容以 [交付验证记录规范](verification-standard.md) 为准。契约是人和模型均能阅读的专业 Markdown，不要求输出编排专用 JSON 或依赖编排脚本。

## 使用入口与目录

用户明确点名、项目明确选择新体系或新编排明确委派时使用；原 skill、旧 workflow 与 `.workflow` 保持原路径。独立活动无需创建流程状态，也不以其他 skill 是否安装为前置条件。

- 新目标默认使用项目内 `.delivery/YYYY-MM-DD-主题/`，日期取目录创建日。跨日、换会话继续同一目录。
- 默认位置只用于新目标。旧版 `docs/delivery/` 或用户明确指定的同目标目录继续沿用；不为适配新默认位置移动历史文件或改写编排账本。
- 同目标已有明确目录时沿用；独立产物接入编排仍沿用。名称相似不自动证明范围相同；多个候选归属不明时核对，无法确定则记录目录选择缺口，不擅自覆盖或合并。
- 已结束目标后的独立新增改动建立新目录并引用原记录；范围不同的上游材料直接引用，不复制整套正文。
- 本能力报告默认 `verification/001.md`、`002.md`，按一次有边界的活动留存，不按工具调用拆文件。创建前检查现有编号；并行调用方分配唯一记录路径，不能抢占已有记录。
- 原始证据位于同目标目录 `evidence/`，建议按能力及记录 ID 分子目录避免冲突。只建立实际需要的产物，不预建空五阶段文档。
- `index.md` 只记目标、边界、来源和产物导航，不维护第二份实时进度。组合时调用方可负责导航，避免多人同时改写。
- 本 skill 不创建或修改 `runtime/`。已有指定路径则按用户范围处理，不能强制迁移；项目产物不放入 skill 安装目录。
- 正式活动默认留存，包括失败、阻塞和部分结果。用户明确仅对话或不落盘时遵从，报告没有可供读取的文件。保存受阻时交付当前内容与真实原因，不宣称已保存。

## 最小输入与输出

输入：验证目标与范围、验收要求来源、实际交付物版本、相关环境、必要权限和可用证据。缺少正式计划不阻止明确要求的独立验证；缺少证据不能补写成通过。

输出：要求覆盖、方法与预期、实际执行和证据、逐项符合/不符合/未验证/不适用、限制、补验关联和后续条件。

各报告记录下列公共身份信息，具体内容可合并在文档说明和相关正文，不以固定标题或字段排列作为专业质量判据：

| 信息 | 要求 |
| --- | --- |
| 目标与范围 | 工作目标、任务/审查组/验收项等实际标识；不存在正式 ID 时可用明确文字定位 |
| 报告身份 | 能力、记录 ID、位置、时间、作者、报告版本及前次关联 |
| 生成规则 | skill 名称 `delivery-verify`、契约版本 `1`、实际 skill 修订 |
| 输入依据 | 相关需求/设计/计划的可定位内容与版本、真实授权或确认来源 |
| 产品身份 | 实际产品版本与有影响的未提交改动，必要交付物指纹及可恢复来源 |
| 结果与限制 | 本能力结论及覆盖、不确定项、失败和阻塞；不得替代其他能力结论 |
| 后续关联 | 后续需要什么、原问题/记录关联、建议失效范围或补充检查 |

skill 修订可以是可恢复的仓库提交；skill 文件有未提交改动时补对应差异或内容快照，不只记 HEAD。无版本库时记录内容指纹与可恢复来源；确实未知则说明缺口，不编造哈希、确认或可复现承诺。契约版本、skill 修订、报告版本、产品版本分别记录。产品工作区存在未提交/未跟踪内容时也不能仅用 HEAD 代表实际对象；按范围留存快照或差异及所需文件。

## 权威与接纳

需求、设计和正式确认是规定行为的依据；本报告是特定范围和版本的事实或专业判断，不授权降低要求。独立使用由用户决定后续，组合时由调用方核对契约兼容、范围、版本、真实授权、结论及未决项后决定接纳。

调用方可生成引用 Markdown 与实际快照的机器接纳记录，但那是调用方的责任，不要求本 skill 读写其运行格式。机器记录不替代专业报告，字段齐全不证明语义判断正确。

本 skill 不主动组织跨能力链，不改写其他人的结果或编排状态。已有独立报告接入组合时核对有效性，不补造历史授权、假装重新执行或要求无意义重做。单个能力退出不等于完整任务完成。

首版 `delivery-orchestrate` 有一个具体接纳限制：独立报告和仍适用的证据可以保留并经核对复用，但组合流程中声明为 `command` 的验收门禁，需要引擎新取得的真实 `run` 回执及一致的产品版本；当前不支持把外部已执行命令导入为引擎运行记录。这是组合接纳要求，不要求独立验证使用引擎，也不要求重做其他能力。调用方应先评估重跑的副作用与授权，不能伪造历史回执或改成 `inspection` 规避原规定方法；无法安全重跑时保留待验状态及具体缺口，不把旧证据改写成新运行。

## 历史与修订

工作记录成稿并被用于后续判断后，保持可追溯；补充或纠错应新建关联记录，说明替代范围与理由，不能覆盖原失败或悄悄改为通过。记录中的明确笔误可修正，但需保留修改说明，已绑定内容发生变化需通知调用方重新核对。

对照实际变化指出哪些旧判断可能受影响，不擅自删除证据或判定整个目标失效。用户接受风险的事实独立记录，不能回写技术符合；新要求引用新版本，旧记录保持其原语义。

维护 skill 时区分内部方法更新、兼容扩展和不兼容契约变化。新增必需输入、删除必要信息、改变结论/门禁含义或降低质量要求都需影响评估；有破坏性变化时升级契约并同步受影响的调用方。文案和方法改进仍需代表性行为验证，版本号相同不自动证明质量不下降。进行中流程不悄悄切换规则，历史记录不按新版本批量改写。本 skill 不自动同步旧体系。
