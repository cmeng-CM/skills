# 实现审查记录：填写审查主题

> 使用说明：替换提示文字，删除本说明；发现数量由实际证据决定，无发现也要说明覆盖和限制。

| 文档说明 | 内容 |
| --- | --- |
| 目标、范围与记录 ID | 填写本次审查对象与边界 |
| 审查者、实现者与独立性 | 填写实际身份关系，不能满足则说明 |
| 时间与报告版本 | 填写真实值 |
| skill 与契约 | delivery-review；契约版本 1；实际 skill 修订及来源 |
| 输入依据与产品基线 | 需求版本、实际差异/产物及未提交内容 |
| 关联记录 | 原审查、修复记录与稳定问题 ID |

先概述规格符合性、实现质量、阻断问题和审查限制。

## 1. 审查依据与范围

说明查阅的需求、实际产物和必要调用上下文；区分阅读、运行复现和未检查范围。

## 2. 规格符合性

| 要求与来源 | 期望行为 | 实际位置或缺失证据 | 判断及关联问题 |
| --- | --- | --- | --- |
| 填写要求 | 可观察行为 | 精确指向 | 符合/不符合/尚不能判断 |

## 3. 实现质量

围绕相关风险说明实际检查的机制、异常和集成路径，给出依据及限制，不堆砌无关检查项。

## 4. 问题与证据

### R-填写稳定编号：触发条件与错误结果

- 证据性质：确认缺陷、待核实风险或建议。
- 触发与预期：填写输入、前置状态、操作及应有结果。
- 实际与证据：填写实际行为及定位；遗漏可说明需求、预期位置与缺失。
- 影响与严重度：说明实际后果。
- 是否阻断及理由：与严重度分开判断。
- 类型：blocker / defect / observation；blocker 按影响和可复现证据判定，不能只按 severity 映射；final 必须重新 triage observation。
- 处置状态：填写真实状态，作者声明修复不等于复审解决。
- 修复方向与后续：说明必须恢复的性质及客观复查条件；建议实现不是唯一修复方式。

复审时保留原问题 ID，说明实际修复检查、相关影响和新结论。final 报告写明被审 config/版本、完整交付覆盖、独立验收证据、unknown/有限交付，以及 final 审查者是否独立于实现者、批次审查者和 verifier。

## 5. 审查结论与后续

分别给出规格符合性与实现质量结论、未解决 ID、未覆盖范围、独立性限制和后续条件。结论为“存在阻断问题”或存在未闭环发现时，附条件清单（问题 ID、所需动作、修复 commit、复审者、复审结论）；复审结论为空的行处置状态冻结在“作者声明已修复，待复审”，未闭环不得转述为通过。复审说明是否扩大范围及理由；不要把局部审查当整体审查或交付验收。
