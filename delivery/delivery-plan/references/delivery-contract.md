# Delivery Plan 交付约定

本文件定义 `delivery-plan` 的输入输出语义契约，当前版本为 **1**。规划内容以本 skill 的 plan-standard 为准；能力不依赖编排引擎，是否组合可用须以实际接纳和验证结果判断。

## 独立使用与工作目录

本 skill 是实现规划的统一入口，普通规划请求、用户点名或 Delivery 编排委派均可进入。单独调用本能力不授权其他能力或完整流程。

用户可以直接调用本 skill。先核对目标、输入材料、授权范围及已有决定；不要求其他 delivery skill、编排脚本或 `.workflow` 存在。没有独立方案时允许使用明确需求或已确认讨论，缺失的关键机制必须先澄清。

正式生成、调整或审阅默认留存文件，包括条件草稿、审阅发现和未完成原因。用户明确只讨论、只在对话交付或不写文件时遵从，不把对话输出描述为已保存产物。仅审阅允许保存审阅报告，不授权改写被审阅文档；保存失败时报告真实原因和待保存内容。

- 未指定位置的新目标使用项目内 `.delivery/YYYY-MM-DD-主题/`。日期取工作目录创建当天，不因跨日或换会话改名。
- 默认位置只用于新目标。旧版 `docs/delivery/` 或用户明确指定的同目标目录继续沿用；不为适配新默认位置移动历史文件或改写编排账本。
- 同一目标已有明确工作目录时继续使用，独立活动后接入编排也沿用该目录。相近名称不等于同一范围；有多个候选或归属不明时先澄清。
- 已结束目标后新增的独立改动建立新目录并引用原记录。适用范围不同的上游设计或计划只引用，不为凑齐文件复制一份。
- 默认计划文件为 `plan.md`；正式计划审阅记录可保存为 `plan-reviews/001.md`、`002.md` 等，按一次有边界的审阅留存，不按工具调用分文件。它们不是实现审查记录。
- 首次建目录时保存简短 `index.md`，仅记录目标、边界、依据和实际产物链接；不维护第二份实时进度。只创建本次需要的文件，不预建空设计、实施或验证文件。
- 用户明确指定现有文档或其他保存路径时按授权处理，不擅自迁移；能够引用原文时不复制同范围正文。编排入口要求不同归属时先核对，不自行接管旧 workflow 或写入 `.workflow`。
- 本 skill 不创建或修改 `runtime/`；项目材料不放入 skill 安装目录。

## 最小输入与输出

输入至少能识别交付目标与范围、设计依据、相关代码或产物基线、已有决定及其确认情况。输入可以是正式设计、已确认讨论或明确的小改动需求；文档齐全不等于实际就绪。

正式产物在计划定位中保存下列信息；正文已有完整定义时精确引用，不维护另一份可变副本。小文档可以合并表达，不以固定标题作为接纳依据。

| 信息 | 语义要求 |
| --- | --- |
| 产物身份 | 计划或计划审阅、目标、范围、保存位置、文档版本及更新时间 |
| 生成规则 | skill 名称 `delivery-plan`、契约版本 `1`、实际使用的 skill 修订标识 |
| 输入依据 | 设计或内嵌依据、真实确认、相关产品代码基线及有影响的未提交改动 |
| 任务与关系 | 稳定任务标识、交付物、依据、细化状态、依赖类型和客观启动条件 |
| 质量安排 | 审查分组与独立性、提前门禁与整体审查、验收归属、验证组和完成条件 |
| 结论与缺口 | 计划确认与自检分开；当前可交接范围、待细化范围、阻塞原因及解除条件 |
| 交接与变化 | 实际执行记录入口或尚未建立的说明、ID 映射、影响范围与证据有效性建议 |

skill 修订可用可恢复的仓库提交标识；相关文件有未提交改动时还需对应差异记录，不能只记 HEAD。无版本库时使用内容指纹及可恢复来源；确实无法取得则明确记录缺口，不能编造版本或宣称可复现。skill 修订、契约版本、计划版本和被规划产品的版本分别记录。

## 组合使用与历史

调用方提供工作目标、授权边界、输入位置和产物目录，本 skill 按相同内容标准完成规划。调用方依据产物判断能否推进；计划可交接不等于取得实施授权、产物已实现或验收通过。

产物保持可读 Markdown；编排器核对正文后在自身范围内生成机器准入快照，引用原文和实际摘要。该快照是对特定版本的接纳记录，不反向成为计划正文真源，也不要求本 skill 运行编排脚本。来源改变后必须重新核对，不能拿旧摘要放行。

本 skill 不自动调用其他交付能力，不修改调用方的流程状态。独立产物接入编排时需核对范围、版本、真实确认和未决项；不为接入补造历史授权，也不因进入编排重新生成同范围计划。

计划维护任务定义和预先声明的条件，实际实施、审查与验证记录由相应活动负责；组合模式下推进与收尾状态由编排器维护。第 6 章声明这些记录的入口与恢复规则，不另建实时进度副本。已有执行事实只做注明版本的引用。

调整时保留稳定 ID、旧新映射、原问题和变更依据；证据受影响的范围与理由交给调用方处理，不能直接改写证据或运行状态。带限制交付需要明确例外依据，不能通过修改计划把验证不符合或缺证据改成通过。

## 本 skill 的更新要求

每次维护先判断是否影响输入、输出、结论含义、必要质量条件或调用权限。内部方法改进可以保持契约版本；兼容扩展须证明旧调用方忽略新增信息仍然能正确判断；必需输入、字段或状态含义变化需升级契约版本并同步受影响的接入规则与检查。

字段未变但降低审查独立性、门禁或证据要求，也属于需要评估的语义变化。记录影响并验证代表性行为，不以脚本结构检查通过代替质量判断。已有流程不自动切换规则，旧记录不因新版本而重写；是否兼容由实际契约与行为核对决定，不能仅比较版本号。本 skill 独立维护，不自动同步或修改其他专业能力及旧 workflow。
