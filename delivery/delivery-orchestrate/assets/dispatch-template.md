# <能力 / 有边界的任务>交接

## 目标与权限

说明交付成果、包含与排除范围、允许修改的路径、已有用户授权及不可越过的条件。指明本次是实施、审查还是验证，不把发现问题当成自动修复权限。

## 必要输入

给出要读取的 skill 实际路径、需求与设计/计划的准确位置、产品基线、相关现有改动、前置产物和限制。已确认事项保留来源与条件，不重新询问。优先附 `brief --kind ... --target ...` 的结果和必要章节路径，不粘贴整份 plan/design；执行者需要更多内容时按章节路径读取。批准的 plan/design 版本只读，局部偏离写实施记录的偏离段。

| 输入 | 实际来源与版本 | 使用要求 |
| --- | --- | --- |
| 目标、约束与验收 | 完整正文路径及必要章节 | 不可因摘要或上下文预算删掉；未读部分明确标记 |
| 本次 skill | 实际包路径、契约和修订/pin | 不从其他安装副本静默换规则 |
| 前置产物与证据 | 当前可接入版本、未验证项及限制 | 可接入不等于最终验收通过 |

复杂修复或实施转交还需：bug 稳定标识和既有目录、当前轮次、原故障条件、已排除原因与依据、失败实验、实际改动、全部历史实施作者/上下文、未处置实验及未知副作用。明确本次仅诊断还是获准修复。接收方先核对现场，不重复已无新信息的检查。

信息超过上下文时保留完整索引，分段读取或调整有意义的任务边界，不能裁掉必要约束后声称已交接。

## 工作与质量要求

说明完成该任务所需动作、检查、验收归属和必须反馈的情况。编排内实施在第一次编辑前运行 `guard --kind task --target <ID>` 并把 ready/blocked 写入实施记录；未通过不得编辑。同一文件范围保持单写者，审查进行中不编辑被审文件。审查者不得参与相关实现；验证需实际对象和原始证据。复用有效证据时说明版本和范围。

## 返回产物

给出该能力自己的 Markdown 报告位置，要求记录实际 actor/context、skill 修订、产品版本、改动或发现、证据、guard 结果、偏离批准版本之处、未覆盖项及后续建议。报告完成不等于编排已接纳；不让受托者手改 runtime。

fix 返回 `fixes/BUG-标识-简述/NNN/fix.md`，该轮原始材料放在同级 `evidence/`。报告直接承接实施职责，不另写重复正文；index 只导航。已经交接、审查或接纳的轮次保留，后续建立关联新轮次，保留被推翻的判断。编排器接纳具体报告版本，专业执行者不写接入 JSON 或 runtime。

## 协作约束

列出其他作者正在修改的范围、资源冲突和等待条件。仓库没有特殊要求时，完成一个功能完整的批次后默认本地提交；记录本批提交，不 push。遇到重大歧义保留事实、候选处理和影响，按已授予的质量优先决策权限处理。

明确工作树路径、Git index、共享测试数据和生成目录的读写模式、持有者与交还条件。中断点记录已做/未做、未知进程/副作用、最后持久操作与下一安全动作；未核查运行不重放。审阅者获得全部真实作者/上下文排除集合，不以换标签制造独立性。
