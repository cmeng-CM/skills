# 接入与演进

编排接入语义契约当前版本为 **2**。历史工作继续支持契约 1；五项基础专业契约及可选 fix 专业契约均为 1。新工作使用显式 v2，详见 [v2 API](runtime-api-v2.md)；[v1 API](runtime-api.md) 仅解释旧契约，不自动追加新保证。

## 内容与机器接纳的分工

五项基础能力及可选 fix 自带内容标准和语义契约，当前均为版本 1。普通对应请求可自然进入；主模型依据实际目标、任务归属、影响和协调需要选择专业处理或编排，不要求逐项目另配入口。专业能力完成自己的范围，不递归启动其他能力；需要后续或升级时由主模型按已有授权安排。它们可以没有编排器、没有 `.workflow`、没有 Git、没有其他 delivery 技能而独立工作；输入信息缺口按实际影响判断。正式活动保存可读 Markdown，用户明确只对话或不落盘时遵从，不能声称已经有文件证据。

编排器读取正文后形成 JSON 接纳快照，JSON 字段和执行 API 按工作契约选择：契约 2 使用 [v2 API](runtime-api-v2.md)，既有契约 1 使用 [v1 API](runtime-api.md)。快照存放编排记录中，不要求作者同步维护第二份计划。来源变化时快照过期，重新读取和映射后接纳；源正文和快照矛盾时以实际来源查明，不能为消除检查报错篡改专业结论。

## 各能力最少承接内容

| 能力 | 输入至少明确 | 输出必须能定位 | 不可当成什么 |
| --- | --- | --- | --- |
| design | 目标、事实依据、范围、决定与确认 | 机制、契约、验收、限制、确认条件和未决项 | 用户批准、已实施或已实测 |
| plan | 设计依据或明确需求、实际基线、权限 | 任务、稳定标识、细化、依赖、审查与验收归属、记录入口 | 执行状态或实际通过证据 |
| implement | 要实现的边界、约束、实际基线和检查要求 | 实际改动、作者、产物版本、自检、偏差和遗留 | 独立审查或最终验收 |
| fix（可选） | 故障与预期依据、授权范围、实际现场、既有调查和作者 | 诊断链、根因确定程度、实验处置、实际修复、自检限制及多轮续接 | 独立审查、最终验收或风险接受 |
| review | 要求、实际改动、相关上下文、独立身份 | 规格与质量判断、问题、证据、阻断性、修复关系 | 修改产品的授权或实测全部通过 |
| verify | 验收标准、实际产物、环境和前置条件 | 预期/实际、原始证据、逐项符合/不符合/未验证及限制 | 风险接受或整个流程结束 |

每份正式产物还需工作目标、实际路径、文档版本、生成 skill 和契约版本、实际 skill 修订、输入依据与基线、结论适用范围和未覆盖项。产物内已有定义可精确引用；不要求所有信息重复成一套模板。

独立产物导入时，核对版本和真实确认，不补造当时不存在的批准或运行记录。缺历史修订时记录缺口，按影响决定重新检查；不要捏造摘要。设计或计划可以引用跨目标上游材料，但不能把它们当当前目标产物直接改写。

独立小型开发使用一份简短实施记录，必要语义、身份与实际版本仍保留；纯机械维护不强制开发记录。明确范围内的独立任务可按必需检查判断本次完成，不伪称独立验收，也不为其自动制造后续门禁；正式编排的独立性、证据和收尾要求仍按原契约执行。

首版不导入外部命令运行回执。已有独立验证报告可以阅读和复用其中仍有效的依据，但 `command` 验收通过仍需本引擎执行声明命令并生成当前 `run` 回执，再由验证者判断。应先评估重跑的副作用与成本；不能安全重跑时保留待验缺口，不能把方法改成 `inspection` 绕过原命令要求。该限制不要求重写已有专业报告，也不允许假装独立执行当时已经运行过引擎。

## 版本与质量演进

区分四种版本：skill 实际修订、对外语义契约版本、专业文档版本、被交付产品版本。Git 提交未包含当前指令时，补充实际差异或可恢复来源；不能只记录 HEAD。引擎保存已接纳文档和证据的原始对象，v1 的实际 skill 修订仍由调用方如实采集；v2 实际读取包文件、保存可恢复对象和 pin，并校验执行包，不能只填 HEAD 或自报字符串。

| 变化 | 处理 |
| --- | --- |
| 方法、解释和示例改进，不变输入输出与质量要求 | 可独立更新，验证原行为仍可用 |
| 可选信息扩展，旧调用方忽略后仍能正确判断 | 可保持兼容，增加正反案例 |
| 必需输入、结果字段、状态含义或门禁变化 | 升级契约版本，同步受影响接入、检查与示例，再组合启用 |
| 字段不变但降低独立性、覆盖或证据标准 | 按语义变化处理，不能视为纯文案 |
| 当前流程遇到未知契约或不兼容修订 | 保留已有记录，停止受影响接纳，定位原规则或显式迁移 |

引擎按工作 init 事件分发：旧请求 schema_version=1、contract_version=1，新工作显式使用 2/2，日志容器仍为 1。未知或混用版本拒绝；v1 不原地升级。这个数字只标识格式，不证明输出语义、真实授权和质量。原有两项文档检查器也不检查全部编排字段，不把其成功当作接纳成功。

新增版本先验证独立场景，再验证组合的成功、失败、未知、修复、证据失效与关闭恢复。历史记录按原规则解释，不批量改写；默认不让进行中的工作静默换规则。新旧 skill 无自动同步关系，旧目录保持不变。

恢复协议有独立版本边界：原 run-resolution 属于恢复子契约 1；显式声明 recovery_contract_version=2 的 run-investigation 与 recovery_transfers 属于恢复子契约 2。顶层编排契约仍为 2，五专业接口不变。子契约 2 仅调整调查到重规划的衔接，不改变最终验收门槛。旧请求/记录按旧规则解释；旧引擎因未知事件种类拒绝新日志，不允许把新协议当可忽略字段。详细输入与启用路径以 [v2 API 第 7 节](runtime-api-v2.md#恢复子契约-2旧命令不再适用时转接当前计划) 为准。

## 可选复杂修复接入

fix 是实施任务可选的专业执行能力，不增加固定阶段或第二套运行引擎。未选择时保持 implement 默认路径，也不要求 fix 包或空修复文件。独立 fix 不依赖编排 JSON、运行状态或兄弟 skill；在组合中仍由协调者完成语义接纳和状态操作。

顶层编排契约仍为 2，实施子契约版本为 1。采用前通过 `enable-fix` 显式登记 `implementation-protocol` 事件，configure 才能声明 `implementation_routes`；旧引擎因未知事件拒绝新日志。启用不代表计划准入、修复完成或验收通过，不解除来源、独立 gate、未知运行、范围变化和资源门禁。旧 v1 不启用该扩展，原 v2 不新增必填字段。活动源码先按 source-update 合法接纳，不能借启用绕过旧 pin。详细格式见 [v2 API](runtime-api-v2.md#可选复杂修复接入实施子契约-1)。

实现类记录仍为 `kind=implementation`，fix 路线绑定真实 fix pin 和 bug 目录具体轮次的 `fix.md`；不复制 implementation 正文，也不靠目录名猜测来源。回执明确 `implementation_skill` 及完整 `implementation_authors`，作者集合含当前 actor 并累积历史实际实施者。相关独立审查和兼容来源审阅排除整个集合，换路线、重配置或只填最后一位作者不能消除历史。来源采集可选增加 fix 契约 1；未选 fix 的任务不受其存在与否影响。

修复报告与证据按 bug 集中，`index.md` 只导航；正式接纳绑定具体轮次与产品版本。已接纳或交接轮次不覆盖，后续形成关联新轮次。新配置的路线变化按正常 change、适用 gates 和复用检查处理，旧 implement 结果不能直接顶替新 fix 结果，问题、失败与验收责任保留。诊断进展在报告表达；通过结论须同时满足授权修复与所需自检，未知或只完成诊断不形成实施通过。

## 首版边界

机器接纳不具备自然语言全义理解、身份认证或真实用户来源认证能力。明确身份、来源摘录、对象摘要和独立复核共同构成可追溯依据；对伪造输入的抵抗不能靠加一个 `approved: true` 字段解决。

首版用范围快照检测文件新增、删除和修改；对于同文件多任务可能保守要求重新核对。选范围时包含消费者、共享契约和依赖证据，不能只选最小改动行而漏掉真实影响。环境声明变化须重新接纳，未声明的外部环境漂移需要验证者主动报告。

## v2 的强制接纳边界

configure 保存待审快照。mapping_review 恒需独立通过；大任务首次实施及重大重规划还需 plan_review；设计按风险、变更按分类要求对应 gate。前置 gate 的来源/报告过期、scope 外未判断变化、执行来源漂移、未核查未知运行或资源冲突，均阻止相应 record/run/close；limited 不能豁免。专业审阅按各 skill 标准执行，映射审阅必须反查完整正文，不能仅检查 JSON 自洽。

v2 不接收手填 skill_revision。skill_sources 要求实际包根，包内普通文件和可执行位保存到对象库；专业 Markdown 契约声明使用“当前版本为 **1**”这一可读标记，编排本文件声明 2，采集时核对实际声明与接入版本。包内文件不能靠改版本号伪装兼容；文件内容摘要不证明兼容语义。实际加载的 runtime 入口和模块必须来自同一执行包并匹配所用 pin。

范围外变化需要绑定当前变化集的明确影响判断；无关变化允许复用，相关变化定向失效及传播，历史失效不撤回。当前 work 自动排除全树监测，但其中来源与证据仍逐文件绑定；其他派生记录目录只能明确理由且不覆盖真实来源/产品。符号链接不跟随，特殊文件只采元数据并提示处置。

未知 run-started 保留原事实；释放资源不等于核查副作用。原 resolve-run 保存调查证据后可允许新 op 重试；显式恢复子契约 2 可在副作用查清后把未完成责任带入新计划，不要求执行已撤销命令。两条路径都须新的真实运行和新 verdict 才能支持收尾。解除依据过期重新阻塞。资源是单工作协调协议，不是系统沙箱或分布式锁；非 Git 项目仍可使用，本引擎不提交或 push。

同源 Markdown/JSON 诊断、brief 和 source 导出支持新会话恢复。历史 v1 保持原规则；要取得新保证新建关联 v2 工作重新接纳，不自动导入旧回执或修改旧日志。
