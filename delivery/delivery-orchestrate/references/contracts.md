# 接入与演进

## 内容与机器接纳的分工

五项能力自带内容标准和语义契约，当前均为版本 1。它们可以没有编排器、没有 `.workflow`、没有 Git、没有其他 delivery 技能而独立工作；输入信息缺口按实际影响判断。正式活动保存可读 Markdown，用户明确只对话或不落盘时遵从，不能声称已经有文件证据。

编排器读取正文后形成 JSON 接纳快照，JSON 字段和执行 API 以 runtime-api.md 为唯一实现规范。快照存放编排记录中，不要求作者同步维护第二份计划。来源变化时快照过期，重新读取和映射后接纳；源正文和快照矛盾时以实际来源查明，不能为消除检查报错篡改专业结论。

## 各能力最少承接内容

| 能力 | 输入至少明确 | 输出必须能定位 | 不可当成什么 |
| --- | --- | --- | --- |
| design | 目标、事实依据、范围、决定与确认 | 机制、契约、验收、限制、确认条件和未决项 | 用户批准、已实施或已实测 |
| plan | 设计依据或明确需求、实际基线、权限 | 任务、稳定标识、细化、依赖、审查与验收归属、记录入口 | 执行状态或实际通过证据 |
| implement | 要实现的边界、约束、实际基线和检查要求 | 实际改动、作者、产物版本、自检、偏差和遗留 | 独立审查或最终验收 |
| review | 要求、实际改动、相关上下文、独立身份 | 规格与质量判断、问题、证据、阻断性、修复关系 | 修改产品的授权或实测全部通过 |
| verify | 验收标准、实际产物、环境和前置条件 | 预期/实际、原始证据、逐项符合/不符合/未验证及限制 | 风险接受或整个流程结束 |

每份正式产物还需工作目标、实际路径、文档版本、生成 skill 和契约版本、实际 skill 修订、输入依据与基线、结论适用范围和未覆盖项。产物内已有定义可精确引用；不要求所有信息重复成一套模板。

独立产物导入时，核对版本和真实确认，不补造当时不存在的批准或运行记录。缺历史修订时记录缺口，按影响决定重新检查；不要捏造摘要。设计或计划可以引用跨目标上游材料，但不能把它们当当前目标产物直接改写。

首版不导入外部命令运行回执。已有独立验证报告可以阅读和复用其中仍有效的依据，但 `command` 验收通过仍需本引擎执行声明命令并生成当前 `run` 回执，再由验证者判断。应先评估重跑的副作用与成本；不能安全重跑时保留待验缺口，不能把方法改成 `inspection` 绕过原命令要求。该限制不要求重写已有专业报告，也不允许假装独立执行当时已经运行过引擎。

## 版本与质量演进

区分四种版本：skill 实际修订、对外语义契约版本、专业文档版本、被交付产品版本。Git 提交未包含当前指令时，补充实际差异或可恢复来源；不能只记录 HEAD。引擎保存已接纳文档和证据的原始对象，实际 skill 修订仍由调用方如实采集。

| 变化 | 处理 |
| --- | --- |
| 方法、解释和示例改进，不变输入输出与质量要求 | 可独立更新，验证原行为仍可用 |
| 可选信息扩展，旧调用方忽略后仍能正确判断 | 可保持兼容，增加正反案例 |
| 必需输入、结果字段、状态含义或门禁变化 | 升级契约版本，同步受影响接入、检查与示例，再组合启用 |
| 字段不变但降低独立性、覆盖或证据标准 | 按语义变化处理，不能视为纯文案 |
| 当前流程遇到未知契约或不兼容修订 | 保留已有记录，停止受影响接纳，定位原规则或显式迁移 |

首版引擎支持 schema_version=1、contract_version=1，拒绝未知版本。这个数字只标识格式，不证明输出语义、真实授权和质量。原有两项文档检查器也不检查全部编排字段，不把其成功当作接纳成功。

新增版本先验证独立场景，再验证组合的成功、失败、未知、修复、证据失效与关闭恢复。历史记录按原规则解释，不批量改写；默认不让进行中的工作静默换规则。新旧 skill 无自动同步关系，旧目录保持不变。

## 首版边界

机器接纳不具备自然语言全义理解、身份认证或真实用户来源认证能力。明确身份、来源摘录、对象摘要和独立复核共同构成可追溯依据；对伪造输入的抵抗不能靠加一个 `approved: true` 字段解决。

首版用范围快照检测文件新增、删除和修改；对于同文件多任务可能保守要求重新核对。选范围时包含消费者、共享契约和依赖证据，不能只选最小改动行而漏掉真实影响。环境声明变化须重新接纳，未声明的外部环境漂移需要验证者主动报告。
