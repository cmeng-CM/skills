# 维护、升级与验证范围

专业规范的权威在五个各自自足的包内；编排接入的权威在本包 contracts、对应版本 API 和实际引擎。修改前先指出具体缺口，复用已有机制，不给每项质量要求另造状态机。

| 变化 | 需要同步的内容 | 充分验证的方向 |
| --- | --- | --- |
| 解释、示例、方法改进 | 受影响入口、规范、模板、示例，保持原输入输出 | 包检查；对应真实专业案例，确认未改变结论含义 |
| 兼容可选扩展 | 契约说明、调用者忽略该信息时的行为 | 旧输入正例、新输入正例和未知/错误输入 |
| 必需输入、状态含义、独立性或门禁变化 | 新语义契约、接入、代码、示例、案例 | 单项、组合成功/失败/未知/修复/更新/恢复；原版相同案例比较 |
| 引擎/持久化变更 | 版本路由、读取、原子写入、事件与对象、恢复说明 | 历史关闭样本、活动续接、损坏拒绝、操作幂等、运行中变化 |
| 包路径或安装变化 | 当前入口、安装目标、源码映射及说明 | 文件摘要、链接和单包抽取实际调用；历史路径不批改 |

字段未变但降低质量约束仍是语义变化。版本号相同、内容 hash 不同或仅声明“兼容”都不能替代影响判断。专业五包独立调用时记录自己使用的实际修订；编排时按 API 采集真实 pins。无可恢复来源的历史缺口如实记录。

## 活动流程与历史

- 新任务显式选用契约 2；省略新 init 参数仍是旧契约 1，为旧命令保留行为。
- 已有 v1 不原地改写为 v2。需要新保证时新建关联 v2 目标重新审阅/接纳，旧报告作输入依据，不冒充新运行回执。
- v2 恢复核对当前实际加载引擎和专业包。原样搬路径、同契约兼容修改、不兼容修改分别按 source-update 处理；新源码不能无记录替换旧规则。
- 恢复子契约 2 需在 resolve-run 显式声明并在 configure 明确承接；仅升级包不启用。旧 run-resolution 维持原义，新 run-investigation 使旧引擎拒绝该日志。来源正文已变时可以先独立接纳修复包，再调查旧副作用；接纳来源不代替新计划准入。具体步骤见 [恢复 API](runtime-api-v2.md#恢复子契约-2旧命令不再适用时转接当前计划)。
- 关闭事件保持当时事实；后续变化先 reopen 或另建新目标。旧来源缺失、解除证据过期、未知副作用均不得静默通过。

## 检查与真实评测

`scripts/check_suite.py` 只检查包结构和可识别本地链接。`scripts/validate_suite.py` 复用该脚本和三组确定性回归，输出同源 JSON/Markdown 及完整日志。它不调用模型，也不作语义批准。

`scripts/evaluate_suite.py` 明确冻结对应案例和 skill，调用真实模型，保存执行轨迹/产物。评审在执行后绑定实际版本；缺接口、超时、泄露或隔离不足不能当通过。维护用测试和私有参考答案不放进被测输入；公开需求和正常项目测试仍提供。具体 CLI、隔离及案例见 [评测说明](../tests/evaluation/README.md)。

对高影响变更先冻结基线与评价标准，再在共同适用场景比较旧版/候选版。必要的完整流程与中断恢复初始重复执行，差异诊断保留全部结果。质量不合格时不能用更快、更省 token 抵消；少量案例也不能证明所有大任务无退化。

## 人和模型共同阅读

专业报告说明依据、真实变化、方法、预期/实际、结论和限制。机器字段必须有解释；派生状态和简报从统一状态对象生成，不能要求作者手工同步两份进度。原始证据保留，报告精确引用；不能只写“passed”或贴大量无结论日志。
