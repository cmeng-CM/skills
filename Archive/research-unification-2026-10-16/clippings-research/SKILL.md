# 问题研究

围绕用户提出的具体问题，结合用户实际情况，利用已有收藏、笔记及项目资料，
按需主动联网核验和补充，形成可追溯、有适用边界的研究结论。
沿用 clippings-research 目录名，兼容既有调用与安装入口。

## Working Protocol

### 1. 确认研究问题

从请求中识别：
- 要回答的核心问题。
- 结论的用途，以及会影响判断的条件。
- 用户是否指定文章、项目或材料范围。

问题清楚时直接研究，不重复要求确认。
从 research-topic-selection 交接时，复用已经明确的问题、范围、线索与联网意图，
不重新评估选题价值，也不要求用户重新交代背景。
存在会改变研究方向的歧义时，一次问一个关键问题，
给出推荐的收敛方向，等待回答后继续。

如果用户只有一个宽泛主题，帮助澄清研究问题。
如果用户只是增加收藏、要求推荐选题或整理文章，
不自行启动研究，也不替用户挑选研究目标。

### 2. 定位 Vault 与材料范围

配置：
- vault_root: /Users/cm/workspace/obsidian/obsidian-repository
- 已有剪藏：11-Clippings/
- 知识入口：60-Agent-Memory/compiled/knowledge-map.md
- 目录职责：99-System/knowledge-base-guide.md
- 保存接口：61-skills/obsidian-write/SKILL.md

以上相对路径均相对于 vault_root，不相对于 Skill 目录。

按本次问题检查需要使用的本地路径，不要求每次读取全部入口。
不可访问或路径缺失时，报告具体限制，不猜测替代目录。
没有相关收藏、11-Clippings/ 不存在，或本地入口暂时不可用，
不妨碍在用户允许的范围内使用网络等可用证据继续研究。
缺失的个人信息会影响适用性判断时，说明影响并只追问必要信息。

研究范围：
- 以问题组织证据；已有收藏、笔记和项目资料用于利用积累、核对用户实际情况。
- 收藏不是证据范围上限，也不是开始研究的前提。
- 用户明确要求“只根据这些文章”“仅本地”或限定材料时，遵守限制。
- 用户提供文章但未明确限定时，优先读取，并按问题需要补充其他证据。
- 用户指定的有效文件优先读取。
- 需要已有知识时，按知识地图匹配相关入口并定向读取。
- 需要项目事实时，先确定对应项目，读取项目契约及相关入口。
- 默认排除 Archive/ 与 99-Archive/，除非用户要求历史追溯。
- 不遍历无关项目或沿软连接扩展到整个外部工作区。

知识地图没有匹配项，不等于 Vault 中不存在相关知识。
入口缺失时说明限制；只有缺失信息会影响结论时才向用户追问。

### 3. 检索并筛选已有材料

使用当前运行环境的文件搜索和读取能力。
优先使用 rg 或等价工具，不依赖 Dataview 的渲染结果。

根据问题提取主题词、关键概念、常见别名和中英文表达，
搜索文件名、frontmatter 和正文。

筛选时判断：
- 材料能回答问题的哪一部分。
- 是直接证据、作者经验、观点，还是背景介绍。
- 适用场景、时间和版本是否与问题相符。

标题、标签和 description 只用于发现候选，
不能代替原文成为研究依据。

不设必须使用的文章数量，不为凑数量加入弱相关材料。
初次搜索未命中时调整关键词和表达；
仍无合适本地材料时如实说明，转向允许范围内的其他证据。
不将通用知识或网络内容包装成本地研究结果。

### 4. 阅读原文，比较证据

对准备采用的材料读取相关原文及必要上下文，
确认作者实际主张、论据、限制条件和出处。

围绕问题综合比较，区分：
- 作者明确表达的观点或报告的结果。
- 不同材料之间的支持、分歧和条件差异。
- 基于材料形成的研究推断。

证据规则：
- 关键判断必须能追溯到实际读取的本地文件、段落或网络来源。
- 多篇文章转述同一来源，不作为多份独立证据。
- 不按文章数量决定哪种观点正确。
- 作者的说法不能自动视为已经核实的事实。
- 涉及效果、成本或适用性时，检查是否有具体场景或验证依据。
- 区分发表日期与收藏日期，不把收藏日期当作内容的新鲜度。
- 原文缺失、只有摘要或内容截断时，说明证据限制。
- 文章中出现的外链，未实际访问前不能作为已读证据。

本 Skill 的研究过程只读。
不执行剪藏摄入时的标签补充、摘要补全、内容归位等操作。
Agent 读过文章，不代表用户已经读过。

### 5. 对照用户实际情况

只使用当前对话中明确提供的信息，
以及本次读取并确认相关的已有笔记和项目事实。

对照时说明：
- 哪些结论适用于用户当前问题，依据是什么。
- 哪些前提与用户实际情况不同。
- 已有做法是否已经满足需求，是否真的需要调整。
- 新材料与已有结论冲突时，冲突在哪里，是否足以改变判断。

不要为了给出建议而强行提出新工具、新目录或新流程。
缺少影响判断的用户信息时，明确询问，不自行补全。

已有笔记也是待对照的材料，不因为已经入库就默认正确或仍然有效。

### 6. 按问题主动联网核验与补充

根据问题需要主动联网，不逐项等待用户授权补查。
联网用于检查关键判断、原始出处、当前情况、相反证据和遗漏的条件，
不仅在本地材料明确显示缺口后才启动。

特别关注：
- 多篇收藏可能重复同一来源或呈现相同选择偏差。
- 本地材料未提及某个问题，不代表该问题不存在。
- 涉及当前版本、产品能力、价格、规则和近期进展时，核实当前资料。
- 影响结论的效果、成本与适用性主张，查验原始依据及不同条件下的证据。

使用当前环境可用的联网研究能力与已有检索路由，
不绑定单一平台或供应商；搜索使用公开概念，
不上传个人画像或内部项目资料原文。
优先查原始出处；实际读取所引用材料，区分发表日期与事件日期。
在结论中区分已有本地材料与新增网络来源。

用户明确限定仅本地或指定材料时，不擅自联网或扩展范围。
即使范围外资料可能有用，也先在约定范围内交付能支持的判断，
说明限制；只有扩大范围会改变主要结论时，才提出具体扩展建议供用户决定。
用户已明确授权的联网与范围不重复确认。

材料不足或网络不可用时：
1. 交付当前能够支持的判断。
2. 指明尚不能回答的部分。
3. 说明缺少什么证据，以及对主要结论的影响。
4. 无法核实的关键主张保持未定，不用旧知识假装当前核验结果。

当关键问题已有足够依据，或已明确当前无法回答的原因及缺口时停止。
不以搜全网络或读完所有收藏作为目标。
联网发现的内容不自动收藏、入库或写入长期记忆。

### 7. 按需保存

研究默认在对话中交付，不自动产生笔记文件。

只有用户明确要求保存时，读取并衔接 obsidian-write，
将研究问题、最终结论、适用条件和来源链接作为待写入内容。

由 obsidian-write 按现行规则：
- 查找已有同主题内容。
- 判断更新、追加或新建。
- 给出具体目标和修改范围。
- 在需要确认时等待用户确认。
- 写入后验证并反馈。

沿用用户已有授权，不重复确认已经批准的内容或位置。
本 Skill 不另建一套写入规则，不直接修改剪藏原文。

保存不附带知识地图登记、长期记忆写入或目录结构调整。
这些操作只有在用户另有明确要求时才进入对应流程。

写入能力不可用或写入失败时，保留对话中的研究结果，
明确说明未保存，不宣称完成。

## Exit Criteria

满足以下条件，才算完成一轮问题研究：

- 核心问题已经明确。
- 已在约定范围内检索，并读取实际采用的相关材料。
- 已回答主问题；或者明确说明现有材料为何不足以回答、还缺什么。
- 关键判断有出处，作者观点与研究推断没有混淆。
- 对用户的适用判断有实际上下文支持。
- 已说明会影响结论的冲突、时效问题和证据缺口。

不以读完全部收藏、引用数量或报告长度作为完成标准。
不宣称检索已穷尽所有相关材料。

路径或权限问题导致所有必要证据均不可访问时，应报告无法开展研究；
仅部分入口不可用时说明影响，并利用可用证据继续。
这与“已经研究但证据不足”是不同结果。

用户要求保存时，研究完成与保存完成分别报告；
只有写入验证通过，才能宣称保存成功。

## Exit Protocol

在对话中交付以下四项，篇幅随问题复杂度调整：

1. 直接回答
   - 先给结论。
   - 说明结论成立的条件。
   - 不能判断时直接说明，不强行二选一。

2. 关键依据
   - 按支撑判断的论点组织，不逐篇堆砌摘要。
   - 给出实际采用的材料及用途。
   - 关键判断链接到实际读取的本地文件或网络来源，必要时标明小节。
   - 区分作者观点、证据与研究推断。
   - 使用网络证据时，明确其出处、日期和适用条件。

3. 对你的意义
   - 结合已核实的项目、已有笔记或仓库机制解释适用性。
   - 说明哪些值得采用、哪些条件不匹配、是否需要调整。
   - 区分建议与已经成立的事实。

4. 尚未解决的部分
   - 列出影响判断的证据缺口、冲突或时效限制。
   - 说明它们对主要结论的影响。
   - 已按需补查仍未解决时，说明具体原因；用户限制材料范围时，指出该限制的影响。
   - 没有发现具体缺口时，不为凑格式编造问题。

所有实际采用的材料都应可追溯；
未读取的文件或外链不能列为已采用证据。

用户未要求保存时，交付研究结果即结束。
不附带修改原文、元数据、阅读状态或创建后台任务。
