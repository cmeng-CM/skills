# Research Router

联网找资源的统一路由：**判动作 → 判资源类型 → 查垂直站点表 → 组合执行**。

本 skill **不替代任何搜索工具**，只决定"这件事该用哪个、按什么顺序、以及什么时候不该用哪个"。判据全部来自实测——凡标"实测"的都真跑过，凡没跑过的一律标"未实测"。

**守卫：**

- **只做路由。** 具体的检索、抓取由被路由到的工具完成。
- **不适用**：只取一个已知 URL 的正文（直接上 `tavily_extract`）、查本地文件、在已知仓库里定位某段代码（那是 grep / gh）。
- **与 `last30days` 的分工**：它管"最近网上怎么说"（时间窗 + 互动量），本 skill 管"找资料"。拿它当通用搜索是错配。
- **与 `agent-reach` 的关系**：它的 `references/` 是六份各平台命令手册，仍然有用；但它的 `SKILL.md` 里那条标准规则（先跑 `agent-reach doctor`）**在本机不可执行**——那个 CLI 没装。两者冲突时以本 skill 的硬约束为准，因为那些是实测出来的。
- **一次会话内不要重复探测同一个工具的状态。** 探过一次就记下来用，别每次重来。
- **加新站点要守规程。** `references/sites.md` 里有收录规程，核心是"实测过再写进去"——本表最贵的教训就是猜出来的路线全是错的。

**反模式（全部来自真实事故，不是假想）：**

- **穷举任务用了检索工具。** 典型症状：知道有个目录站、甚至引用了它，却没进去。看到"某站上都有什么"要立刻切成穷举动作。
- **用 `WebFetch` 取需要事实、表格或原文的页面。** 它经小模型二次摘要，实测三次丢内容（GitLab 页面只回了导航栏、Google 那个模板被答"文章不含"、arc42 只拿到一半）。要事实就换 `tavily_extract`，同一个 GitLab 页面它 0.12 秒给全了。
- **找代码用网页搜索。** 网页搜索引擎对代码的索引质量很差，GitHub 一律走 `gh`。
- **在已知仓库里猜文件路径。** 先 `gh api .../git/trees/<branch>?recursive=1` 列树。
- **拿 `last30days` 当通用搜索**，或**依赖 `tavily_research`**（本机两次超时，含 mini 档，不可用）。
- **照抄 `agent-reach` 的 standing rules**（`doctor` 不存在、Exa 路由未配、零配置命令表里 `mcporter call 'exa...'` 那条是死的）。
- **把"这个源没有"和"这个源没查成"混为一谈**——超时、限流、未登录、未配置都不等于没有。

## Working Protocol

### 第 0 步：判动作（选工具之前必须先过这一步）

| 动作 | 什么时候 | 用什么 |
|---|---|---|
| **检索** | 不知道有哪些，先要一批候选 | `tavily_search` / `gh search` / `last30days` / 垂直站 |
| **穷举** | 已知有个源，要它下面的**全部**条目 | `tavily_map` / `tavily_crawl` / `gh api tree` |
| **取正文** | 已有 URL 或已知文件，要原文 | `tavily_extract` / `curl` / `gh api contents` |

判据就一句话：**我要的是一批候选，还是某个已知源的全部？** "某个站上都有什么"是穷举。

### 第 1 步：判资源类型 → 谁索引得最好

| 资源类型 | 主路线 | 为什么 |
|---|---|---|
| 代码 / 仓库 / skill 文件 | `gh search code --filename <文件名> "<词>"` | 按**文件层**搜，绕开仓库名与描述的措辞差异；网页搜索对代码索引差 |
| 网页文章 / 博客 / 技术文档 | `tavily_search`（`advanced`） | 直接带正文，不经过二次摘要 |
| 目录站 / 文档站的全量 | `tavily_map` → `tavily_extract` | 穷举 |
| 近 30 天的讨论 / 风向 / 互动量 | `last30days` | 时间窗 + 互动量是别的工具给不了的 |
| 中文视频 | `bili search "<词>" --type video -n 5` | 免登录可用 |
| Reddit | `rdt search "<词>" --limit 10` | cookies 可用 |
| X / Twitter | ✗ **当前不可用**（未登录） | 需要先解决凭证 |
| 原始文件（raw / 仓库内文件） | `curl` 或 `gh api … \| base64 -d` | **零摘要损耗**，别经过任何摘要工具 |
| 需要 JS 渲染的页面 | `browser-use` | 前几条路线都拿不到时 |

### 第 2 步：查垂直站点登记表

读 `references/sites.md`，看有没有对口的站。有 → 按登记路线走；没有 → 走通用检索，并在交付时说明"没有专用站"。

**这一步最容易被跳过**，因为"直接去搜"的冲动最强。判据：**某类资源如果存在专门的聚合站，通用检索一定不如它全**——skills.sh 就是靠这条进来的（在它上面搜能搜到 `gh search code` 漏掉的 skill）。

### 第 3 步：按组合拳执行

**拳一 · 找"某类项目 / 同类实现"**
```
gh search code --filename SKILL.md "<词>"     ← 文件层检索，命中率最高
    ↓ 发现有价值的仓库
gh api "repos/<o>/<r>/git/trees/<br>?recursive=1"   ← 穷举该仓库文件（别猜路径）
    ↓ 遇到不确定的页面
tavily_map / tavily_extract
```

**拳二 · 找"某类资料 / 知识"**
```
tavily_search (advanced) × 多组关键词并行     ← 一级：找入口、摸分布
    ↓ 拿到关键站点（如 designdocs.dev）
tavily_map                                   ← 二级：穷举它的条目
    ↓ 挑中的条目
tavily_extract (advanced)                    ← 三级：取正文
```
**纪律：第二级最容易被跳过，第三级不能省。** 停在"我知道有这么个地方"等于没查。

**拳三 · 看"风向 / 最近怎么说"**
```
last30days "<话题>"      ← 主场；时间窗 + 互动量
    ↓ 需要补静态资料时
tavily_search
```

### 第 4 步：交付时声明覆盖

- 说清查了哪些源。
- **失败的源单独列**：超时、限流、未登录、未配置 —— 这些都不等于"那个源没有"。
- 覆盖不到的部分明说，不要用"没找到"盖住"没查"。

## Exit Criteria

- [ ] 动作判对了：穷举任务没有只用检索工具
- [ ] 取正文没有经过会丢内容的工具（`WebFetch` 只用于"要个大意"）
- [ ] 查过 `references/sites.md`，或说明了为什么没有对口的站
- [ ] 原始文件走的是 `curl` / `gh api`，没经过摘要层
- [ ] 覆盖范围显式声明；失败与未配置的源单独列出，没有混进"没有"里
- [ ] 发现值得长期用的新站时，**提议**登记而不是擅自写入

## Exit Protocol

**呈现顺序**：

1. **结论先行**——先给答案，再给来源。
2. 每个关键结论标出它是在哪个源上成立的。
3. **覆盖与缺口单列一节**：查了哪些、哪些没查成、哪些是部分覆盖。
4. 全程只用了通用检索而没有专用站时，说明这一点（下一个人可能该把那个站登记进来）。

**发现新站时**：说明它覆盖什么、你是怎么查到它的、以及它比现有路线多给了什么——然后**问用户要不要登记**，不要直接改 `references/sites.md`。登记要按那里的收录规程走。
