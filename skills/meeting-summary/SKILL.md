# Meeting Summary

把 AI 记录的会议内容提炼成三类条目——**关键决策、行动项、遗留问题**，每条附转写原文摘录作依据。默认终端展示 Markdown，用户要求时落成文件。

**守卫：**

- **忠实转写，不补戏。** 总结只从转写里提取和压缩，绝不添加转写中不存在的信息。缺失字段标「未提及」，需要推断处（如某句话的归属）标「存疑」。
- **摘录一字不改。** 原文摘录必须与转写逐字一致（允许用「…」截断）。改写摘录等于伪造依据。
- **没有就是没有。** 宣讲、培训、读书会类会议没有决策和行动项——如实报告「未发现」，不硬凑。空章节是 feature。
- **语言跟随原文。** 转写是中文总结用中文，英文总结用英文；对用户本人的说明永远用中文。
- **边界。** 本 skill 只做单场会议的结构化总结。多场会议跨会对比、行动项导入任务系统、自动排期不在范围内。

**反模式（明确不要做的事）：**

- 不要把某人不确定的随口一句升级成决策——只有明确拍板或达成一致、且无反对的才是决策
- 不要把「遗留问题」写成「行动项」——有人认领且任务明确的才是行动项；没人接、没时间点的待议事项归遗留问题
- 不要用自己的话解释摘录——摘录本身就是依据，读者自己读
- 不要擅自覆盖同名输出文件——先询问
- 不要在结尾空转地问"还有其他要求吗"——输出总结并报告统计即可

## Working Protocol

### Step 0: 获取输入

- 用户粘贴了文本 → 直接使用。
- 用户给了文件路径（可多个，视为同一场会议的拆分，按给出顺序拼接）→ 读取文件；🔴 **文件不存在或读取失败 → 终止并向用户核实路径，不猜用别的文件。**
- 文本 < 50 字 → 说明过短无法提炼，终止。
- 超长文本（估算 > 30k 字）→ 分段处理：每段独立提取三类条目，最后合并、按语义去重；每条保留所属段的摘录。

### Step 1: 通读定位基本信息

先完整通读一遍全文，再动手提取。记录会议主题/议题、参会方、日期——转写里没有的字段标「未提及」，不推断，也不查外部资料补。

### Step 2: 提取三类条目

提取前先按时间线走一遍，标记所有「拍板点 / 任务认领点 / 悬而未决点」，再归类——按语义找事件比按句子找类别不易漏。

**关键决策**：明确拍板或各方达成一致的结论。含：结论本身 + 拍板人（如可辨认）+ 关键理由（转写有才写）。判断标准：有"定了 / 就这样 / 同意 / 按这个来"类表述且无反对。

**行动项**：任务内容 + 负责人 + 时间点。三个字段转写没提的分别标「未提及」。判断标准：有人认领且任务内容明确。

**遗留问题**：被提出但未解决、被搁置、待下次讨论、或结论模糊存疑的事项。与行动项的边界：无人认领或无明确任务的归遗留问题。

### Step 3: 每条附原文摘录

- 摘录是转写原句，一字不改，允许「…」截断。
- 摘录必须能支撑该条结论——摘的是"我觉得行"就别写"决策：全面重构"。
- 摘录与条目不能互相矛盾；若发现矛盾，说明读漏了，回 Step 1 重读。

### Step 4: 输出

终端渲染 Markdown（中文转写示例）：

```markdown
# 会议总结（2026-08-18）

## 会议信息
- 主题：xxx
- 参会方：xxx

## 关键决策（2）
1. **决策内容**（拍板人：张三｜理由：xxx）

   > 转写原文摘录（多行摘录每行以 `>` 开头）

2. …

## 行动项（3）
1. **任务内容** — 负责人：李四；时间点：本周五

   > 转写原文摘录

## 遗留问题（1）
1. **问题描述**（背景：xxx，如有）

   > 转写原文摘录
```

规则：

- 摘录一律用 Markdown 引用块（行首 `>`），多行摘录每行都加 `>`；条目与引用块之间空一行，保证任何渲染器下都是标准引用样式。
- 某类为空 → 该节写「无」，不删节。
- 三类全空 → 明确报告「未发现决策 / 行动项 / 遗留问题，该记录可能为宣讲 / 培训类会议」，并按边界说明本 skill 不做宣讲内容摘要。
- 英文转写 → 结构不变，标题与条目用英文（Decisions / Action Items / Open Questions），摘录保持原文。
- 结尾报告统计：决策 n 条、行动项 m 条、遗留问题 k 条。

### Step 5: 写文件（仅用户要求时）

- 命名：`会议总结-YYYY-MM-DD.md`（英文会议用 `meeting-summary-YYYY-MM-DD.md`；日期取今天，`date +%F`）。
- 位置：文件输入 → 与会议记录同目录；粘贴输入 → 当前工作目录；用户指定路径 → 用用户路径。
- 🔴 **同名文件已存在 → 先告知并询问：覆盖 / 加序号（-2、-3）/ 换路径。不擅自覆盖。**
- 文件内容与终端输出完全一致。

### 失败分支（触发条件 → 一线修复 → 仍失败兜底）

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 文件路径不存在或读取失败 | 终止，向用户核实路径，不猜用别的文件 | 列出当前目录候选文件让用户重选 |
| 粘贴文本 < 50 字 | 说明过短无法提炼，请补充文本或改用文件路径 | 用户坚持 → 输出基于现有文本的诚实版，明确标注「信息不足」 |
| 全文皆是寒暄闲谈，无实质内容 | 正常过滤，不写进总结 | 按「三类全空」报告 |
| 转写语言混杂（中英夹杂） | 以主体语言为总结语言，专有名词保留原语言 | 各条摘录保持原文，不加翻译 |
| 同名输出文件已存在 | 询问覆盖 / 加序号 / 换路径 | 用户未响应 → 默认加序号，绝不覆盖 |

## Exit Criteria

- [ ] 三类条目每条都有原文摘录，摘录与转写逐字一致（允许「…」截断）
- [ ] 全文无转写中不存在的信息；缺失字段已标「未提及」，推断处已标「存疑」
- [ ] 输出语言与转写主体语言一致
- [ ] 空类已如实写「无」，未删节；三类全空时已明确报告并说明边界
- [ ] 已报告条目统计（决策 n / 行动项 m / 遗留问题 k）
- [ ] 用户要求写文件时：文件名、位置符合规范，同名冲突已询问；未要求时已提示一句可落盘

## Exit Protocol

1. 终端展示总结 + 统计行。
2. 用户未要求写文件 → 提示一句：「需要落盘的话，我可以存成 `会议总结-YYYY-MM-DD.md`」——一句即可，不追问。
3. 行动项非空 → 附带一句提醒用户核对负责人 / 时间点（AI 转写在此类细节上易漏）。
4. 结束，不替用户决定下一步。
