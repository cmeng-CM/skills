# Handoff 文档模板

文件名：`.handoffs/<YYYYMMDD-HHmm>_<task-slug>.md`（时间戳前缀使文件名排序即时间序）

填写原则：
- 写给下一个对本次对话一无所知的 agent，不是写给自己的备忘
- 空章节保留标题写"无"，不使用 `[TODO]` 占位符
- 只装"重新发现成本高"和"未完成"的信息；架构全景、代码常识不写

---

```markdown
---
chain: <任务短 slug，如 auth-refactor>
seq: <链内序号，从 1 开始>
prev: <上一份 handoff 文件名；新链写 null>
branch: <生成时的 git 分支>
base_commit: <生成时的 HEAD 短 SHA>
created: <YYYY-MM-DD HH:mm>
---

# Handoff: <任务标题>

## 当前状态

一段话：在做什么、现在什么状态、停在哪。关键位置给到 `文件路径:行号`。

## 客观状态锚点

- **分支**：xxx（handoff 之后有无新 commit 由 RESUME 方用 base_commit 核对，此处不预测）
- **本次会话 commits**：N 个（`git log --oneline -5` 摘录）
- **未提交变更**：N 个文件（`git status -s` / `git diff --stat` 摘录）
- **测试**：通过 / 失败 / 未运行

## 已完成

- [x] 事项 —— 一句话说明做了什么（功能性描述，不揣测动机）

## 进行中

- 当前任务 + 停下的具体位置（`file:line`），下一个动作是什么

## 待办

- 未开始的任务
- 被阻塞的事项 + 阻塞原因

## 关键决策

| 决策 | 考虑过的备选 | 选择理由 |
|------|-------------|---------|
| 选了 X | X / Y / Z | 为什么选 X、为什么否掉 Y |

## 坑与失败方案

重新发现成本最高的信息，必填；本轮确实没有则写"无"。

- 踩过的坑：现象 + 根因 + 规避方法
- 试过但失败的方案：方案 + 失败原因（防止下一个 agent 重蹈覆辙）
- 不显而易见的代码行为/环境怪癖

## 未回答的问题

上任 agent 向用户提出但未获回答的问题，原样记录。RESUME 方必须原样重问。
没有则写"无"。

## Resume Command

> 读取 .handoffs/<本文件名> 并继续 <任务>。下一步：<第一个具体动作>。
```
