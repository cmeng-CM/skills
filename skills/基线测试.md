# Skill 质量基线测试

本仓库所有 skill 的验收标准与执行规程。评分引擎为 darwin-skill 2.0（9 维 rubric），本文定义"怎么算合格"和"怎么跑"。

## 验收三件套（每个 skill 必须具备）

1. `SKILL.md` —— 按 `模板.md` 四段式
2. `test-prompts.json` —— ≥3 条 `[{id, prompt, expected}]`，覆盖：最典型场景（happy path）、歧义/边界场景、易误触发场景
3. 基线评估记录 —— 在 darwin-skill 的 `results.tsv`（`~/.claude/skills/darwin-skill/results.tsv`）中有 `baseline` 行

## 判定标准

| 判定 | 条件 |
|---|---|
| ✅ 合格可发布 | 总分 ≥ 80，gate 全过，dim8 为 full_test |
| ⚠️ 可用但有短板 | 70–80，针对最低维度修一轮后复测 |
| ❌ 需优化 | < 70，或 dim8 显示"带 skill 比不带还差"（不论总分都否） |
| ❌ 硬性失败（分数无效） | 缺 test-prompts.json / runtime 红灯命中 / dry_run 比例 > 30% |

**Gate 项（一票否决，先于评分执行）**：

- runtime 红灯扫描：`grep -nE "(在 Claude Code|Claude Code skill|Claude Code 用户|Cursor only|Codex 中|~/\.claude/skills/[a-z])" SKILL.md` 必须无输出（frontmatter 触发词等正当引用除外）
- skill 必须能在 Claude Code / Codex / OpenCode / CodeBuddy 等任意 skills-compatible runtime 运行

## 执行规程（何时跑、怎么跑）

**触发时机**：新建 skill 后、修改 SKILL.md 后、定期巡检（建议每季度或模型大版本升级后）。

**跑法**：对 darwin-skill 说"仅评估 `<skill名>`，不做 git 提交"（即只跑 Phase 0.5–1，不进优化循环）。规程要点：

1. test-prompts.json 已存在则复用，不重写
2. 结构维度（1-7、9）由 **2 个独立 judge 子 agent 盲评取均值**——不允许主 agent 自评
3. 效果维度（8）必须 full_test：with_skill vs baseline 对照；**baseline 子 agent 须明确禁止读取仓库内的 skill 文件**，否则实验被泄漏污染（2026-08-04 session-handoff 首轮实测踩过此坑）
4. 结果记入 results.tsv，eval_mode 列如实标注 `full_test` / `dry_run`

**优化后复测**：改动 SKILL.md 后必须重跑评估，新总分严格高于旧分才保留改动（棘轮机制）；连续 2 轮 Δ < 2 分即触顶收手，不为凑分加冗余。
