# 实施取舍与需查看事项

用户授权原则见 authorization.md。以下是实施者按质量优先选择的细节，不是用户逐字段确认；后续变更保留原理由与替代关系。

| 项目 | 采用方案 | 理由、影响与后续查看重点 |
| --- | --- | --- |
| Markdown 与机器接口 | 五能力独立交付 Markdown；编排侧生成绑定正文摘要的 JSON 准入快照 | 保持可读性和独立性。JSON 的映射正确性必须语义审查，机器不能证明全文理解正确 |
| 状态存储 | 单工作目录原子事件账本、文件锁、内容寻址对象 | 避免多个可变状态文件互相漂移；支持本机进程协调，不承诺分布式多写者 |
| 新旧入口 | 新系列显式选择；Codex 配套 explicit-only policy，其他客户端用入口文字约束 | 不修改旧skill，不假设每个客户端都支持同一配置字段 |
| 版本变化 | 来源/范围变化先失效或待核对，明确重新接纳后才复用 | 优先防止过期证据放行；同文件多任务可能保守增加核对成本 |
| 人工确认和独立身份 | 保存真实来源摘录和参与者标识，脚本核查引用与冲突 | 不把可编辑记录当密码学身份或真实用户授权的独立证明 |
| 修复循环 | 发现有新证据的修复继续；同一失败连续两轮无实质进展时换诊断并记录 | 防止无限原样重试；授权范围内可换方法，不能自行扩大权限或降低验收 |
| 未完成的编排器自举 | 先由本次明确授权组织实施与独立审查，待引擎可用后接纳真实产物 | 不用旧 .workflow 控制同一目标；不把前期人工动作伪装成过去已运行的引擎事件 |
| 限定交付的首版边界 | 仅允许逐项豁免已实证失败且计划允许豁免的验收；实施和独立审查仍须通过 | 缺证据、过期证据、失败的独立审查不能被例外吞掉；比允许任意问题级豁免更保守 |
| 有问题历史的重规划 | 保留问题所属审查/验收目标和关联任务的稳定 ID；可增设新分组和整体审查 | 独立审查发现，删除旧责任目标会使历史问题永久无法处置。首版在配置接纳前拒绝该变更，不支持跨目标迁移；即使曾解决也保留身份，因为证据变化后可能重新待确认 |
| 独立命令证据进入编排 | 专业报告可按有效性复用；command 门禁仍需引擎真实运行回执 | 首版未实现外部命令证据导入。重跑前评估副作用，不能安全重跑则保持待验，不改验收方法绕过；后续可基于真实使用需要设计受约束导入 |

实际发现、剩余局限和最终需要用户查看的内容，完成后在本文件末尾补充；不写入长期记忆。
