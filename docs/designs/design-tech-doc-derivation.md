## 一句话方案

把 `design-tech-doc` 的"组合约束推演"从已写到的规则落实为有产出物的步骤——耦合场景逐场景记录「操作前状态 → 操作 → 操作后状态 → 约束是否仍成立」，未决语义逐条显形——并加入一个新领域迁移用例，用 full_test 对照检验既有规则的执行效果；不改技能整体结构。

## 背景与目标

### 承接关系（自生来源）

承接 `docs/designs/design-tech-doc-consensus.md`（该技能现行设计记录；已冻结）。继承其已交付的：逐项共识协议、三类文档与三档评审、独立状态、十五类语义模块、与 task-workflow 的十节机械契约、审阅规则对照面。`SKILL.md`、`references/review.md`、`test-prompts.json`（23 例）为现行文本，本次只做增量修正。

### 问题现状

2026-10-14 用该技能生成 `docs/designs/workflow-review-granularity.md`（task-workflow 方案门稿件）后的评审结论（对话，无文档承载）：

- 该稿的主要提升可归因于用户此前给出的十点修订建议与"重写方案"指示，不能归因于技能独立发现设计问题；
- 技能已写到组合约束要求（`SKILL.md` §3 组合约束段落与 Exit Criteria、`references/review.md` 审阅口径），但生成未产出这些规则要求的推演结果：稿中"上游失效、两轮封顶后恢复、终审等待、记账中断"四类交互语义只有规则、没有推演，且未标记为未决；
- 正式评分报告自认案例 15 的成功"属于规则应用证据，不能推断未知场景的泛化改善"（技能内已有与该案例同构的示例）。

不改的后果：规则继续停在文字层，"首次实战未见产出"的模式会重演；测试集无法区分"记住了已知案例"与"能把推演迁移到其他设计"。

### 预期结果

1. 存在状态流转、生命周期或多机制交互的设计，在成文前产出「操作前状态 → 操作 → 操作后状态 → 约束是否仍成立」的推演记录（成立的关键记录进正文相应机制处；未决的成文前逐项提问或随稿逐条显形）；
2. 关键结论的来源归属（用户已确认／尚未确认的建议／继承附适用依据／待实测）与未决、推迟项在成文前简报核对；未决、推迟项随稿逐条显形；
3. 新增迁移用例（夜间对账作业，与已知案例不同领域）在 full_test 对照中检验：改动后新版应表现出推演、逐项提问与拒绝宣告闭合；既有用例不得退化；
4. 评分与验证按仓库规程（`基线测试.md`）记录，结论、限制与"不能外推"的口径如实入档。

关键约束：不改技能整体结构（不做整套重写）；`references/review.md` 本次不动（审阅侧已覆盖，缺口在执行不产出）；不新增分类词汇；验证必须独立执行者＋独立盲评，执行者不读 expected 与其他输出；不推送。

## 做法

### 推演步骤（SKILL.md §3）

把"复用共识前检查组合约束"升级为"推演"步骤：加触发判据（状态流转、生命周期或多机制交互——一次操作改变多个不变量，或机制间状态耦合）、产出形式（逐场景四元组记录，只覆盖耦合场景、保持简短）、产出物去向（成立的关键记录留在正文相应机制处供核对；不成立或缺保障机制的按一次一问协议逐项提出）、反规避（机制重述、术语对齐、检查项列全都不算推演成立——堵住"重述即闭合"）。`Exit Criteria` 同步为可核对口径。既有示例段（v0/v1/v2 三版本共存）保留，不加新示例。

### 来源与未决显形（SKILL.md §3 简报检查点 + §4 工作流联用）

成文前设计简报增加两项核对：关键决策与结论的来源归属（四类，沿用既有"已确认／待确认／待实测＋继承附适用依据"词汇，不建新分类）、未决与推迟项（含推演未决的语义）逐条列出、不静默省略。工作流模式补一句：方案门可以作为成稿方案的确认点，但成文前的组合约束推演不因"整体送审"而跳过，未决语义随稿逐条显形——本例的失败模式正是"门会兜底"语境下的推演缺席。

### 迁移用例与回归（test-prompts.json）

新增用例 24：夜间对账作业调度（新领域）。材料以"共识已逐项完成、没有剩余设计疑点"的自信口吻给出各机制（固定源快照、两次重试转人工、人工后可重新执行、检查点恢复、随时取消、总表唯一口径、账本权威），但不含跨机制交互语义；期望行为＝推演并指出核心交互缺口、将最关键一项转为当前唯一决策问题、不擅自补写、不宣告闭合。同时把第 6 项（完整共识直接成文）与第 15 项（组合约束拦截）作为回归用例：新步骤不得导致轻量设计被误停，也不得让既有拦截退化；第 8 项（条件草稿）纳入对照以核实证分支未被波及。

### 验证安排（按仓库规程）

结构层：`quick_validate`、测试集 JSON 形状与唯一 ID、runtime 红灯扫描、引用可达性、`git diff --check`，加独立语义审查（核对 D-NN 承载与文本一致性）。行为层（full_test 对照）：条件＝改动后新版／改动前版本 `614e544`／不加载 Skill；用例＝24、6、8、15；每条件每用例独立新上下文、执行者不读 expected 与其他输出、无 Skill 组禁止读取任何仓库 Skill；两位未参与实现与前轮审阅的评审者按相反顺序盲评匿名候选；门槛＝用例 24 新版行为通过、6/8/15 无行为退化、新版总分 ≥80、严格高于改动前版本、未劣于不加载；结果按规程追加至 `~/.claude/skills/darwin-skill/results.tsv`（旧历史保留），并回写本记录。与上轮 87.70 的对比因案例集不同不直接可比，如实标注；出现持平或下降时按规程呈报用户裁定，不自行加码或回退。

## 备选与取舍

| 备选 | 没选的理由 |
|---|---|
| 只加规则文字或再加一个同构示例 | 评分报告已自认"同构示例＝规则应用证据"；重复老路不能证明迁移，必须给产出物与迁移检验。 |
| 照搬四分类新词汇（用户已确认／建议待确认／继承约束／待实测假设） | 技能已有三清单＋继承指针＋决策摘要来源列；新增平行分类造成词汇漂移。改为沿用既有词汇表达同一区分。 |
| 把状态矩阵设为所有设计的必做项 | 轻量单机制设计背矩阵，违背按深度与风险裁剪；以触发判据限定为状态/多机制耦合设计。 |
| 本轮同时修改 `references/review.md` 审阅侧 | 审阅侧已覆盖该口径（组合约束检查、C03、C07），实测缺口在生成端不产出，改审阅侧不解决执行。 |
| 整套重写技能 | 单样本文档评审，无证据支持；用户结论为"优先验证并加强现有规则的执行效果"。 |

**残余风险**（由验证与信号检验，不预设接受）：

| 风险 | 触发条件 | 信号 | 处置 |
|---|---|---|---|
| 推演被机械填表 | 执行者按格式填四元组但不真正核对约束 | 记录无场景状态差异、直接宣称成立 | 评审按 C07 核对记录；迁移用例继续检验 |
| 迁移用例被"教成"规则应用 | 技能文本或示例与用例 24 同构 | 用例通过但其它领域仍不产出 | 不在技能内加与用例同构的示例；后续扩充不同域用例 |
| 新步骤误伤轻量设计 | 触发判据被执行者放宽 | 用例 6/23 类输入开始无故停下提问 | 收紧触发判据；回归用例持续覆盖 |
