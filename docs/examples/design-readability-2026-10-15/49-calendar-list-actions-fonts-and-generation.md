# 日历面板：自然语言生成、表单与列表交互改进

> **阅读改写稿 · 2026-10-15。** 本稿用于评审方案的表达方式，尚未替代[原方案](/Users/cm/workspace/github/gourd/docs/49-calendar-list-actions-fonts-and-generation.md)。设计决定与证据来自原稿；本次未重新运行应用、测试或字体测量。原稿状态为草稿，尚未登记实际交付结果。

## 1. 这次要解决什么

这次改动让用户能顺畅地完成三件事：把一句自然语言变成日程，在固定大小的面板里看清并填写表单，直接从列表查看和处理日程、待办。

当前最影响使用的是生成失败。输入“精准维修云平台周会，今天下午三点半，会议时长一个点”时，即使模型按要求引用原文，应用仍可能拒绝结果。与此同时，表单有空位、备注不明显，生成失败后的重试入口也不醒目。列表则把详情和编辑操作藏在较小的点击入口之后。

| 使用环节 | 当前问题 | 本次改动后的行为 |
|---|---|---|
| 自然语言生成 | “三点半”等正常表达可能校验失败 | 补齐钟点解析，保留原文证据校验；生成失败后仍能直接重试 |
| 编辑日程、待办 | 字号小，待办有两处空半格，备注容易落到可视区之外 | 增大文字，合并待办的截止日期与链接行，明确备注输入区 |
| 查看列表 | 主要靠小箭头进入详情页 | 点击整行，在当前面板弹出详情浮层 |
| 处理记录 | 编辑、删除入口不集中 | 面板列表行提供适用的编辑、删除按钮；浮层底部也提供相应动作 |
| 首页“今日” | 点击后离开当前位置 | 就地弹出同一套详情浮层；首页行本身保持现有简洁形态 |
| 列表空间 | 月历与记录区宽度分配不适合本轮交互 | 列表档改为左侧月历 40%、右侧记录 60%，高度不变 |

**有两个代价需要在读方案时就知道：** 40/60 分栏会使“九月初一”这类四字月名副标不再显示；本轮也不增加任意时长解析，原文没有明确结束钟点时，仍按既有条件采用默认一小时。这些限制不能等实现之后才告知使用者。

## 2. 改完之后怎样使用

### 2.1 从一句话生成日程

以用户反馈中的句子为例：

> 精准维修云平台周会，今天下午三点半，会议时长一个点。

模型提取日程并引用“三点半”等原文证据。应用将它解析为下午 15:30，而不是因为带“半”字拒绝结果。由于原文没有明确的结束钟点，模型应让结束时间及其证据一起留空；应用在起点明确、无结束提示的既有条件下补足一小时。

修复包含两个相互配合的动作：解析器理解正常的钟点表达；生成提示约束模型不把推算出的结束时间伪装成原文证据。原文证据校验保持严格，不能为了让生成成功而放宽为“随便引用一句原文即可”。

生成按钮的位置始终不变：

| 状态 | 主按钮 | 用户可以做什么 |
|---|---|---|
| 待生成 | 生成 | 发起生成 |
| 生成中 | 取消 | 取消本次生成 |
| 生成失败 | 重新生成 | 直接重试；也可选择“改为手工填写” |

失败信息保留一行红字。“重新生成”仍是同一个明显的主按钮，不再藏在失败提示里的纯文字操作中。

### 2.2 在固定大小的编辑区填写表单

编辑区自然高度保持 400pt。待办表单把“截止日期”和“链接”排在同一行，移除原来的两处空半格；日程表单的“开始｜结束”“地点｜链接”两行保持原布局。

备注输入区增加浅边框与占位文字，让用户能看见从哪里输入。生成区的原文默认展示三行，超过三行后在输入框内部滚动。

文字采用本稿第 5.2 节列出的具体字号。紧凑布局通过把行距从 10pt 调为 8pt 实现，保留既定字号与控件尺寸。**“400pt 内一屏放完”是待验证的验收目标，原稿的高度测算不能代替上屏结果。**

### 2.3 从列表和首页查看详情、执行操作

点击记录行后，详情浮层固定在当前面板内。用户可以继续查看详情，或使用浮层底部的图标操作；鼠标移开时，面板不会因自动收起而打断查看。

不同入口保持以下分工：

| 入口 | 点击记录本身 | 行内动作 | 详情中的动作 |
|---|---|---|---|
| 日历面板中的可写日程 | 打开详情浮层 | 编辑、删除；会议日程另有一枚会议按钮 | 按记录能力提供打开系统日历、会议动作、编辑、删除等 |
| 日历面板中的可删待办 | 打开详情浮层 | 删除；本批不增加待办编辑 | 按记录能力提供打开系统提醒、完成、删除等 |
| 日历面板中的只读记录 | 打开详情浮层 | 不展示无权执行的编辑、删除 | 展示可用动作和只读原因 |
| 首页“今日”条目 | 在首页就地打开同一套详情浮层，不切模块 | 保持既有会议单图标；不新增编辑、删除 | 复用同一详情卡片，按记录能力提供动作 |

会议入口按原稿较新的 D-19 决定收口为**一枚会议按钮**：点击时打开会议，只有号码时复制；右键显示操作菜单。面板列表仍保留“平台名＋会议号”的信息文字。首页会议按钮保持原有 22×22pt 形态。

面板列表的行内动作组整体靠右，最后一枚按钮贴行内右边距，图标间距 8pt、图标 16pt。详情浮层底部的动作使用图标，文字保留在悬停提示与无障碍标签中。

删除需要在面板内就地确认。关闭详情可用关闭按钮、再次点击同一行或 Esc；切页、收起面板、锚点消失时也必须清理浮层及其固定状态。独立详情页随之退役，打开系统日历和只读原因等内容转入浮层。

## 3. 范围与主要取舍

本轮继承[单草稿与保存前校验](/Users/cm/workspace/github/gourd/docs/39-calendar-light-interactions.md)以及[编辑表单与按档尺寸](/Users/cm/workspace/github/gourd/docs/48-calendar-editor-form-and-mode-size.md)。草稿模型、保存校验、面板整体宽度、手动／自适应尺寸机制和编辑档 400pt 自然高保持原约定。

会议识别继续沿用[既有会议方案](/Users/cm/workspace/github/gourd/docs/47-meeting-entry-and-one-click-open.md)；会议入口的**呈现**按 D-19 改为单按钮。

本轮不包含岛内编辑提醒、不调整月历网格字号、不解析新的任意时长语法，也不处理面板尺寸变化的动画。月历继续使用 `MonthGridLayout` 派生的既有字号（原稿记录已放大至 1.2 倍）。待办编辑需要单独明确 `beginEdit` 的字段、写回 API 及与系统“提醒事项”的分工。

| 选择 | 采用理由与代价 |
|---|---|
| 补解析器，同时收紧模型结束时间输出 | 修复正常表达失败，保留可核查的原文证据；不新增时长语法 |
| 只改提示词绕开“半”，不采用 | 回避了应用解析缺陷，用户仍不能自然表达时间 |
| 放宽证据校验，不采用 | 会失去确定性校验对编造时间的约束 |
| 面板内自绘详情浮层 | 原稿记录非激活 NSPanel 中 NSPopover 不稳定；sheet／独立窗口会打断输入 |
| 只保留浮层这一种详情入口 | 避免详情页与浮层两套行为并存；需要接好列表与首页两个宿主 |
| 增大文字、压缩行距，保持高度 | 尊重字号与尺寸要求；是否一屏容纳必须实测 |
| 左右 40/60 分栏 | 给右侧记录更多空间；四字月名副标会被隐藏，三个字的节日名称余量很小 |

## 5. 实现契约

本节供实施与定向审阅查考。前文约定的交互、限制和验收条件同样具有约束力。

### 5.1 时间解析与证据

入口保持 `services/ScheduleParsing.swift` 中的既有签名：

```swift
private static func clockEvidence(
    _ evidence: String,
    inheritedPeriod: String? = nil
) -> String?
```

| 项目 | 约定 |
|---|---|
| 新支持的词形 | `X点半` → `HH:30`；`X点Y分` → `HH:YY`，分钟支持中文与阿拉伯数字 |
| 识别与解析的一致性 | `timePattern` 能匹配且含义规范的词形，`clockEvidence` 必须能解析；小时 0–23，分钟 0–59 |
| 前导“零” | 支持规范读法，如“三点零五分”→ 03:05 |
| 无效输入 | 越界值及“十零／一十／零十／零零五”等畸形写法沿原路径确定性拒绝 |
| 结束时间 | 只有原文出现结束钟点才输出 `end`；否则 `end`、`endEvidence` 同时留空 |
| 默认时长 | 复用起点明确且无结束提示时默认一小时的既有行为，不新增时长解析 |

原稿的根因证据来自真实解析器与测试桩：“三点半”无法通过证据解析，而改成“下午三点”或原文使用“15:30”可以通过。本稿保留这一证据陈述，不将它冒充本次重新测得的结果。

### 5.3 详情浮层与动作权限

复用 `components/Calendar/CalendarEventDetail.swift` 中的 `CalendarEventDetailsModel`、`CalendarEventDetailsOverlay`、`CalendarEventDetailCard`。日历面板列表以 `@StateObject` 持有详情 model。原稿记录这套组件当时没有运行期宿主，本轮接入日历面板列表与首页今日区。

| 触发或状态 | 要求 |
|---|---|
| 列表行点击 | 调用 `details.togglePin(event.id)`；文字单击也在验收范围内 |
| 浮层挂载 | 使用 `.calendarEventDetails(model: details)`；挂在列／页级，避免置于 ScrollView 内部 |
| 首页挂载 | 今日条目上报锚点，浮层挂在滚动视口之外；复用同一详情卡片 |
