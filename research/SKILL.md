# 问题研究

以问题组织知识发现、检索与论证，回答“目前知道什么、依据是什么、在什么条件下成立”。可独立研究，也可接收 research-topic-selection 的交接；个人资料与具体工具都不是启动前提。

## Working Protocol

### 1. 锚定问题与范围

识别核心问题、结论用途，以及材料、时间、版本等会影响判断的约束。问题明确时直接研究，不重复选题或索要已给出的背景。只有宽泛主题或存在会改变方向的歧义时，问一个关键问题并等待回答，不自行补全目标。

选题交接可用自然语言传递：**问题、用途、范围及约束、已有线索、待验证判断**。复用已明确的信息；只有用户明确要求继续研究才进入本流程，读取检索参考本身不构成研究授权。

- 用户指定的有效材料优先读；“只根据这份文件”“仅本地”“只查网络”等限制决定证据范围。单文件任务不另读个人背景来补强结论。
- 提供材料但没有限定范围时，可按问题需要补充其他证据；允许联网的研究按需主动核验，不逐次请求补查许可。
- 默认做资料研究，不自动安装研究对象、运行其代码、做基准实验或修改项目。资料不能回答的实测问题，说明实验目的与方法；得到明确实测请求后再进入相应执行流程。
- 只有新增收藏通知、整理需求或选题请求时，不自行启动研究。

### 2. 建立必要的知识框架

先弄清回答问题需要哪些概念、它们如何关联、有哪些主要解释或实现路线，再拆成能由材料回答的子问题。把未知概念与待验证主张分开：既查“这个领域如何解释问题”，也查“这个具体判断是否成立”，避免只寻找支持初始猜想的材料。

用初读材料补全框架，并据此扩展检索词：术语、别名、中英文表达，以及能解释同一机制的相关领域。新发现可能要求改写子问题或回读基础材料；扩展必须能说明与原问题的关系。若需要改变研究目标，先交由用户决定。

简单问题可直接形成一条查询，不强制画框架、列阶段表或生成长报告。

### 3. 按证据需求发现与读取材料

需要联网发现、检索或获取原文时，读取 [检索路由](references/search-routing.md)；寻找专门资源索引时，再查 [站点登记表](references/sites.md)。工具随当前环境选择，历史路线不是当前可用性保证。

需要用户的收藏、笔记或项目事实时，读取 [个人资料与保存接口](references/local-context.md)，仅定位相关入口。没有收藏或本地入口不可用，不阻断允许范围内的其他研究。

按子问题选择来源，覆盖有价值的不同视角，而不按固定数量凑来源：

| 要支撑的主张 | 优先寻找的材料与检查点 |
|---|---|
| 概念、机制与理论解释 | 原始论述、研究论文或权威技术资料；检查定义、假设及解释边界 |
| 产品契约、当前能力与实现 | 对应版本的官方文档、发布记录与源码；区分文档承诺、实现观察和实际效果 |
| 效果、成本与适用性 | 原始研究、评测方法及数据、具体案例；核对比较对象、指标、场景和限制 |
| 使用体验、争议与近期讨论 | 当事人记录和社区讨论；用于发现问题与线索，不以热度代替事实或代表性 |

标题、标签、搜索摘要只用于发现候选。采用材料前，读取相关原文及必要上下文；需要数字、表格、代码或准确措辞时检查是否完整。只有摘要、片段或转述时降低证据强度并说明，不能把未访问的外链列为已读依据。

对影响结论的二手主张向后追踪原始依据；对重要原始材料向前查找后续修正、复现、反驳或版本变化。按缺口追踪，不为完成形式而遍历每条引用。

### 4. 比较证据并针对缺口补查

围绕子问题综合材料，区分作者主张、材料报告的观察结果、已核验事实与本次推断。关键判断保留可追溯的文件位置或来源链接；多个材料转述同一来源，只算同一条证据链。

重点检查会改变答案的冲突和反证：

- 分歧是否来自定义、版本、样本、指标、场景或假设不同，而非直接矛盾？
- 支持与反对结论的原始依据各是什么，方法和适用条件是否可比？
- 是否漏掉一种主要解释、失败条件或替代方案？它会怎样改变当前判断？

据此调整关键词、查新的来源类型或追踪引用；补查要对应具体缺口。不能消解的重要冲突保持未定，或缩小结论成立的范围，不按文章数量投票。

核对发表日期、事件日期与版本；收藏日期不代表内容新鲜度。涉及当前能力、价格、规则等易变事实时，在允许范围内查当前资料；无法核实时明确时效限制。

个人适用性只使用对话明确提供、或本次读取并确认相关的事实。已有笔记同样需要核对；缺少会改变建议的信息就询问，不为了给建议而补造用户背景或引入新工具、新流程。

### 5. 判断是否足够并交付

当关键子问题已有足以支持回答的依据、重要反证已处理，且继续补查不太可能改变主要判断时停止；也可以在明确当前无法回答的原因及所缺证据后停止。深度由问题与证据决定，不以检索轮次、来源数或报告长度衡量。

渠道失败、材料缺失或范围限制时，先交付当前能支持的判断，说明未回答的部分及其影响。未查、没查成与查后未发现要分开；有界穷举只能对已核验的范围声明完整，不能推称全网穷尽。

研究默认只读并在对话交付。明确要求保存时，按目标衔接已有写入能力；Vault 保存见 [个人资料与保存接口](references/local-context.md)。不附带修改原文、阅读状态、元数据、长期记忆、目录结构或创建后台任务。

## Exit Criteria

- 主问题与证据范围明确，实际采用的材料已读取并可追溯。
- 已回答问题，或明确哪些部分不能回答、缺少什么及其影响。
- 知识框架足以解释答案；关键主张、推断、适用条件及重要反证没有混淆。
- 会影响判断的冲突、时效限制、渠道失败与覆盖缺口已说明。
- 未越过材料边界或自动开始实验、保存及其他写入。

必要证据全部不可访问时，报告“无法开展所需研究”，不包装成已经研究后的否定结论。部分不可访问时继续利用可用证据，并保留限制。

## Exit Protocol

先直接回答，再按论点给出关键依据、成立条件和仍未解决的部分，篇幅随问题调整，不逐篇堆砌摘要。关键判断链接到实际读取的本地文件或网络来源，必要时标明段落、日期与版本；区分本地材料和新增网络证据。

需要个人建议时，说明哪些条件匹配用户、哪些不匹配及其依据；一般知识问题无需强加“对你的意义”。没有实际缺口就不为格式编造问题。

用户未要求保存时，交付研究结果即结束；要求保存时分别报告研究结果与保存结果，只有写入验证通过才声称已保存。
