# 检索路由

本参考供 research 按子问题选择检索方式，也可由 research-topic-selection 单独读取，支持发现线索与价值判断。读取它不要求启动完整研究、不改变上游目标，也不授权研究对象实验或写入。

## 先分清动作

| 动作 | 目标 | 合适的能力 |
|---|---|---|
| 发现／检索 | 找未知候选、概念、不同解释或实现 | 搜索引擎、学术或资源索引、平台检索 |
| 有界穷举 | 列出指定目录、仓库、分类或时间范围内的全部条目 | 目录/API 分页、站点地图、仓库树、可验证结束条件的遍历 |
| 取原文 | 读取已知页面、论文、文件或讨论上下文 | 原生读取接口、原始文件、正文提取、必要时浏览器 |

“这个站收录了哪些条目”需要遍历目录；“找些资料理解 X”不因发现目录站就必须遍历全站。检索结果、排行榜和一次限量抓取都不等于完整清单。

## 资源与路线

从当前环境实际提供的工具、已安装 skill 及其说明选择；以下是能力示例，不是启动依赖或永久优先级。调用前只确认本任务需要的能力，避免探测无关渠道。

| 资源／证据 | 优先路线 | 补充或降级路线 |
|---|---|---|
| 知识概念、机制、技术资料 | 原始作者、官方文档与学术索引；多组关键词发现不同术语与解释 | 通用网页检索定位原文，沿引用与后续工作追踪 |
| 论文、评测与数据 | 论文原文、出版方或预印本、作者材料及数据仓库 | 二手综述找线索；只有摘要时不推断方法与结果细节 |
| 代码、仓库、skill 文件 | 平台原生搜索、GitHub 连接器或可用的 `gh search code`；按文件名、符号与概念检索 | 仓库搜索、专门目录与网页索引互补；进入候选后读真实文件 |
| 专门资源目录 | 查 [站点登记表](sites.md)，匹配范围后使用其索引或目录 | 通用检索与源仓库补充；目录的收录范围不等于领域全貌 |
| 近期讨论与社区经验 | 对应平台搜索；需要时间窗与互动信息时，可用已安装的 last30days | 其他讨论源或网页检索，注明时间、排序与平台覆盖差异 |
| 已知网页、原始文件 | 原生接口、`gh api contents`、`curl` 或当前可用的正文提取能力 | 页面依赖交互或渲染时用浏览器；仍不完整就标注缺失 |

平台任务可按已安装 agent-reach 的当前说明选择后端；需要其他专用 skill 时先读其当前说明。旧记录不能覆盖当前工具要求，也不能证明本机仍有某 CLI、凭证或登录态。

## 从发现走向深挖

1. 用问题中的术语摸清入口和知识分布，补充别名、中英文、上位概念及相关领域表达；不同关键词应解决不同发现盲区。
2. 找到可靠综述或目录后，读其结构，识别遗漏的概念、路线与争议，再选择与问题相关的原始材料。不要停在“知道有这个站”。
3. 对关键主张追到原始依据，并查后续修正、反驳、复现或版本更新；原始材料也要判断方法与适用性。
4. 把新线索带回子问题：能回答哪一项、改变什么、还缺什么。没有增量就停止该分支，避免无限扩展关联主题。

专门索引、通用检索、代码和社区材料可互补，但不要求每个问题都使用所有来源。多处转载同一内容不增加独立性。平台热度和安装量可辅助发现，不能替代质量判断。

## 取回内容后检查

搜索工具附带的正文片段与摘要未必完整；名为“extract”“raw”的能力也需检查实际返回。核对标题、作者、正文是否匹配，表格、脚注、分页、附件或代码是否缺失；读取足以解释主张及其限制的上下文。

需要准确事实时，不把经过二次摘要的输出当作完整原文。原始文件优先用原生接口或直接读取；网页仅需大意时可使用摘要，但不能据此声称核验了未读细节。

引用来源应是实际读取的材料。通过工具获得转述时说明层次，不能把转述中的外链当作已访问证据。检索使用公开概念，不把个人画像或内部项目原文上传到外部服务。

## 有界穷举的结束条件

先明确要列全的范围，例如某目录当前公开条目、某仓库某个版本的文件，而非笼统“所有相关资源”。遍历时核对：

- API 分页、下一页／游标、总量及重复项，是否到达真实结束条件。
- `limit`、搜索结果上限、crawl 深度与广度，是否导致未覆盖部分。
- 仓库树的 `truncated` 等截断信号；有截断时分层读取子树或改用其他可验证方式。
- 权限、登录、隐藏内容和动态加载是否限制覆盖；站点地图是否只是部分页面。

例如使用 `gh api "repos/<owner>/<repo>/git/trees/<ref>?recursive=1"` 时保留并检查完整响应的截断标志，不能只提取文件名便宣称列全。先确定真实分支或版本，再取文件，不猜路径或默认分支名。

未验证结束条件只能报告部分清单及覆盖范围；扩大参数或多翻一页本身不是穷举完成的证据。

## 失败与重试

记录本次失败的动作、渠道和原因：超时、限流、未登录、未配置、无权限、正文缺失等。失败不代表不存在；替代渠道有不同覆盖，也不能冒充原平台已查。

优先换能满足同一证据需求的可用路线。保持条件不变时不反复探测同一失败；只有错误可能暂时消失、参数或环境已变化等具体理由时才作有限重试。不要依据某次失败永久宣布工具不可用。

交付只说明影响结论的覆盖与失败，无须把每次查询变成长日志。没有发现对口的登记站点时，可用通用路线；不能据此断言不存在专门索引。
