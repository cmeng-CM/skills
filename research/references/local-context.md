# 个人资料与保存接口

只有研究需要个人积累、用户适用性或明确要求保存到 Vault 时才读本参考。直接知识研究、只查网络或限定单文件的任务，无需先定位 Vault、读取个人资料或检查全部入口。

## 本机定位配置

以下沿用原研究包的配置，实际访问前按本次需要核对存在性与权限；它们不是通用环境路径，也不是研究启动条件。

## 定向读取

- 用户明确指定的有效文件优先；限定材料时不额外读取背景来补强结论。
- 需要已有知识时，先按知识地图匹配相关入口，再定向读取。地图无匹配不证明 Vault 没有相关知识；必要时仅在相关范围补查，入口缺失则说明限制。
- 需要项目事实时，先确定对应项目，读取项目契约及其相关入口。不遍历无关项目，也不沿软链接扩展到整个外部工作区。
- 默认排除任意层级的 `Archive/` 与 `99-Archive/`；只有用户要求历史追溯或指定归档材料才读取。
- 用当前可用的文件搜索／读取能力，优先 `rg` 或等价工具；可按主题词、别名和中英文搜索文件名、frontmatter 与正文，不依赖 Dataview 渲染结果。

标题、标签和描述用于发现候选，实际依据来自正文。筛选材料能回答哪个子问题、属于直接证据还是个人观点、适用日期与场景是什么。初查无命中可调整表达；仍无相关材料时如实说明，不把通用知识或网络结果包装为本地发现。

个人笔记不是天然正确或当前有效；区分原始发表日期与收藏日期，核对冲突。缺失的个人信息若会改变结论，说明影响并询问必要信息；不影响一般研究的缺失不必阻断。

## 保存接口

研究默认在对话交付。用户明确要求保存到 Vault 时，读取当前可用的 obsidian-write，将**研究问题、结论、适用条件、来源及未定部分**交给它，按其现行规则查重、确定更新／追加／新建、写入并验证。沿用已明确的内容与位置授权，不重复确认。

用户指定其他输出位置或格式时遵守其请求，使用相应写入能力，不强制转存 Vault。保存能力不可用或写入失败时保留对话结果，并明确尚未保存。

保存研究不附带修改剪藏原文、元数据或阅读状态；agent 读过不代表用户读过。也不附带知识地图登记、长期记忆写入或目录调整，这些需要另有明确请求。研究完成与保存完成分别报告。
